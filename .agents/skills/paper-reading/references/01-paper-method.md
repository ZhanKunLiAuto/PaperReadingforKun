# 论文阅读方法

## 默认深度与用户标杆

用户在 2026-10-19 明确要求：后续解读以其提供的 RoVES 分析为标杆，详细、具体、清晰地读懂并评价一篇论文。此偏好同时适用于对话和 HTML，取代此前精炼核心版、5–8 分钟阅读、1,500–2,200 字目标及超过约 2,500 字优先压缩的规则。

- 首次交付的完整解读就充分解释关键机制、实验和判断。对话把这条论证分轮展开，随用户的选择调整解释顺序。篇幅由论文复杂度和解释需要决定。
- 标杆的核心是“具体事实 → 为什么这样理解 → 能支持什么结论 → 哪些结论仍缺证据”。每个重要判断都应让读者能沿这条链回到原文。
- 语气直接、平实，肯定与质疑都依据证据。根据材料得出判断，不预设论文一定存在严重问题。
- RoVES 示例提供的是分析深度和推理方式；不套用它的结论、领域问题、固定七节结构或 TVT 审稿视角。只有用户要求审稿时才给接收／大修等决定。
- 用户当次明确要求摘要、速读或限定篇幅时遵循当次要求；普通局部追问聚焦当前问题，不重复整篇解读。

## 苏格拉底式导读

备读时，找出一个足以改变你对论文评价的问题，以及一条能检验它的原文证据。可以请读者站在作者当时的位置做一次取舍、在看消融结果前做预测，或决定接下来把有限的实验预算花在哪个对照上。选本篇真正有悬念的一处即可。

**第一轮。** 用一两句给总体判断与适用范围，把待解释的原因留给推理。用一个具体场景交代作答所需的事实，提出一个问题，通常给两三个都有来由、含义确实不同的选项。问到这里就等读者回答。回一个字母即可，也欢迎提出其他解释、索取提示或直接看全文。

**收到选择。** 先把它还原成可检验的预测，再一起看能区分解释的证据，指出具体图表、设置和观察。下一问沿着这个选择推进。比如，读者把提升归于新模块，就先看在相同数据与预算下开关模块的消融；读者归于额外数据，就先核对各组训练数据和规模。若作者同时改了两者，就说明两种解释都还成立，邀请读者设计能把它们分开的对照。上述是选证据的例子，实际只引用本篇已有材料，设想的实验要明说。读者有自己的解释时，沿其理由走；索取提示时先指出图中值得比较的两处，留给读者再判断的机会。

**走到结尾。** 只在读者的选择会改变推理时提问，术语和必要背景直接解释。不同分支可以在同一项关键实验汇合。最后回到读者起初的猜想，用原文指出哪一部分保留、哪一部分需要修正、还有什么分不清，并把这些判断串回论文的贡献与边界。读者要求直接讲、速读或问具体问题时，当轮直接回答。

**在 HTML 中。** 把首问放在总体判断之后或相关论证旁。选择后展示该项的预测、证据入口和相应的下一问，提供改选和跳到对应正文的入口。关键推理用作者预写的本地分支表达，整篇正文从一开始就可连续阅读。自检时实际走两条不同路线：换一个选项，读者应该会比较不同证据、检查不同假设，或从另一个角度读同一张图。

## 分析链

```text
具体问题与价值
  -> 旧方法的瓶颈
    -> 本文改变了什么
      -> 输入、关键模块、输出及作用机制
        -> 实验证据与比较条件
          -> 判断、适用边界与实际启发
```

阅读时明确本次主体是方法、系统、模型、数据集、benchmark 还是技术瓶颈，区分论文事实、官方 repo 事实、作者解释和自己的推断。这条链用于核验，正文按读者的理解顺序组织，不机械复述原文章节。

## 开篇与整体组织

完整正文开篇用一段给出总体判断：它解决什么具体问题，最有价值的贡献是什么，证据支持到哪里，以及最影响评价的限制。随即解释“它到底做了什么”，让读者先建立完整图景；材料或核验范围有缺口时就近说明。逐轮对话按上面的导读节奏开场。

正文围绕适用的问题充分展开，可按论文实际内容合并或调整顺序：

| 读者要理解什么 | 应讲清的内容 |
| --- | --- |
| 它到底做了什么？ | 具体任务、输入输出、使用场景、完整流程；用一个材料支持的例子贯穿关键步骤。 |
| 为什么值得做？ | 原有方法在哪里受限，这个限制怎样影响应用，本文解决了哪一部分。 |
| 方法具体怎样工作？ | 关键模块的操作、数据如何衔接、训练与推理的区别、核心公式与假设，设计选择为什么可能有效。 |
| 新意和价值在哪里？ | 哪些复用已有方法，哪些是新增设计，整体组合带来什么能力；必要时用“模块／实现／贡献评价”对照表。 |
| 实验究竟证明了什么？ | 重要结果及其评测条件、基线、指标、消融和失败情况；逐项解释数字如何支持或限制作者的主张。 |
| 哪些地方还不能下结论？ | 具体证据缺口、潜在混淆因素、适用范围与代价，为什么影响结论，以及什么验证能消除不确定性。 |
| 对本次阅读目的有什么用？ | 已能采用的思路、需要谨慎外推的部分和最值得验证的方向；结合用户明确的研究或工程背景。 |

标题应表达本篇的实质问题或判断，例如“尺寸一致不等于形状可信”，避免只有“方法”“实验”这样的泛称。小标题、表格和列表用于帮助比较与定位，主体仍以连贯段落解释原因。

## 方法与创新：讲清操作和因果

- 对关键模块说明：输入是什么、具体做什么、输出是什么、为什么需要它、依赖什么前提，以及它如何影响下一个模块。不要只列模型名称或重复作者的贡献清单。
- 将作者使用的抽象词还原为实际操作。例如“耦合”涉及哪些变量、传播方向是什么、是否有反馈；区分共享变量、单向传播与闭环响应，结论以当篇材料为准。
- 对关键设计解释“原有瓶颈 → 本文改动 → 预期作用 → 实验证据”。预期机制不等于已经被验证的因果关系。
- 区分新算法、已有技术的应用、系统集成和工程参数选择。系统贡献可以有价值；评价依据是新增能力、对照收益及适用条件，不能仅因模块来自已有工作就否定贡献。
- 当贡献归因不清时，指出能隔离该设计作用的合理对照，例如保持其余条件不变的简化基线。明确区分作者已做的实验、未报告的实验和自己的建议，不把建议当成已运行结果。

## 证据：数字、条件与结论一起读

- 每项重要结果说明测试对象、数据与任务、比较对象、指标含义和方向、数值及单位、影响结论的设置。相对提升与百分点分开，作者报告与本页计算分开。
- 关键定量判断就近标明章节、图表、公式或页码；末尾列出实际使用的论文、官方 repo 等来源。未核查官方实现时，不把论文描述写成已验证的代码行为。
- 按论文主张组织实验分析，解释每组关键结果支持什么、不能支持什么。覆盖改变贡献判断的消融、反例和失败情况，不以固定的结果数量限制分析，也不抄满全部表格。
- 核对评测条件是否与声称的应用一致：数据规模、模型设置、硬件、训练预算、选优策略、开环／闭环、仿真／真实环境等，只展开实际影响当前结论的因素。
- 分清输出变化与准确率变化、代理指标与最终能力、尺寸或格式一致与真实性、局部模块验证与端到端有效性。需要真值或控制变量的结论，不能从展示图或相关变化直接推得。
- 对运行时间、成本和效率写清包含与排除哪些阶段。跨论文设置不同的数字不能直接作为公平排名。
- 核验创新主张时区分“本文如何定位自身”与“经文献比较确认的增量”；未独立检索时不声称已确认首创性。材料没有数值或细节时如实指出，不补造数据。

## 局限与评价：已有证据和缺口分别说清

每项重要质疑按“原文做法或证据 → 具体问题 → 为什么影响结论 → 可澄清的验证”解释。补充实验应对准争议，范围与主张相称，避免泛泛要求“更多数据”或把大型训练实验当成唯一合格证据。

- 先准确承认作者已经做出的验证，再评价它的覆盖范围。作者明示的限制、未报告的证据、自己提出的可能风险与已证实的错误要分别表述。
- 不把“没有证明”写成“已经证明无效”，不把合理假设写成必然失效；机制缺陷或替代解释应说明依据及不确定性。
- 作者谨慎表述时按其真实主张评价，不把“输出受影响”改写成作者声称“准确率下降”后再批评。
- 区分会动摇核心结论的问题、限制外推范围的问题和表达改进，说明优先级。只在确实影响理解或判断时评价写作、图表或实验篇幅。

用户 RoVES 示例中值得延续的推理方式（仅作写法示范，不构成对其他论文的事实判断）：

- 规定长宽高与输出一致，支持缩放实现正确；要声称内部轮廓可信，还需要轮廓或三维几何的验证。
- 相机变化后框的位置改变，可由正常投影解释；要归因于感知误差，需要对应真值或运动补偿。
- 已有动力学对照应得到承认；再比较验证工况与实际编辑工况，指出哪些外推尚未得到支撑。

## 术语、公式与图解

- 术语首次出现时用中文说明含义及它在本方法中的作用；关键概念必要时配具体例子。解释深度以读者能跟上后续推理为准。
- 公式按理解方法的需要展示，不限制为一个核心公式。按“解决什么问题 → 符号、单位与约束 → 运算过程与直觉 → 对输出的影响”解释；涉及关键结论的推导补足中间步骤，不跳过核心假设，也不抄录无助理解的推导。
- 图用于解释流程、变量关系、因果链或方法差异，数量随独立的理解难点决定。图后说明读者应看见的关系，正文继续分析作用、前提和证据，避免逐节点复述。
- 示意例子和玩具计算须标明性质；不得把自己构造的数字、动画或图形当作作者实验。

## 交互与详细正文

- 新建解读或重写机制时，先读 `04-interactive-explainers.md`，为适合的机制实现可操作、可看见变化的交互，不等待追问才补。
- 优先增强已有机制图，展示阶段切换、流程步进或变量作用；正文和静态回退独立保留完整解释、判断、证据与来源。交互辅助理解，不能替代方法与实验分析。
- 重要分析放在正文，不能将理解结论所需的细节藏进折叠区；扩展推导或补充材料可按阅读需要安排。

## 后续交流

- 普通追问先在对话中充分回答当前问题，必要时回查原文。读者作答时结合上一题、选项含义及读者的理由继续导读。用户要求更新正文或处理网页标记时，按 HTML 契约写回。
- 一个标记回答聚焦当前标记，保留必要推理和上下文；个人评论独立保留，不能当作已证实结论。

## 自检

- 开篇是否给出明确而有边界的总体判断？读完后能否具体复述输入、关键操作、输出及模块间关系？
- 是否解释了“怎么做”和“为什么”，还是只堆术语、摘要和结论？理解所需的公式、步骤和实验条件是否已充分展开？
- 重要肯定和质疑是否都有可定位的依据？数字与比较条件是否准确，作者主张、已有验证和自己的推断是否分清？
- 是否解释了实验能支持到哪一步、缺口为何重要、什么对照能回答问题？是否对已做验证给予了准确评价？
- 是否因旧篇幅目标删掉必要分析，或将其推迟到追问？是否存在重复背景、无关细节或为篇幅罗列的材料？
- 适合本篇的机制交互是否已实现并验证有意义的变化？若省略，是否说明针对本篇材料的具体原因？
- 稳定锚点与评论是否保留，可见标题是否帮助读者理解？
