# 论文阅读方法

## 分析链

```text
目的
  -> 主体
    -> 旧瓶颈
      -> 关键动作
        -> 机制链
          -> 证据链
            -> 技术债 / 边界
```

先回答：

1. 研究目的：这项工作要把什么瓶颈、成本或能力缺口，变成什么可用收益？
2. 阅读主体：本次真正要解释的是论文、机制、系统、模型家族、数据集、benchmark，还是一个技术瓶颈？
3. 旧瓶颈：它出现前为什么做不到？
4. 关键动作：它到底改了什么？
5. 证据边界：哪些来自论文、哪些来自 repo、哪些只是推断？

## 输出结构

```text
研究目的
开篇总览图
核心结论
旧世界为什么不够
关键动作
机制链
证据链
技术债
边界
来源
```

## 开头组织

- 研究目的先回答“对象 / 瓶颈 / 收益”。
- 开篇总览图用 SVG 压缩场景压力、旧瓶颈、关键动作、证据方向和结论落点，不重复章节名。
- 核心结论展开完整判断，承接总览图进入正文。

## 公式处理

遇到核心公式时，按以下顺序展开：

```text
公式回答什么问题
  -> 每个符号分别代表什么
    -> 分子 / 分母 / 约束条件的直觉
      -> 这个公式为什么导向论文的关键动作
```

- 先说明公式在算什么，不先堆符号。
- 逐项解释变量，尤其说明“越大越好 / 越小越好 / 只是中间成本”。
- 把公式连接回论文目的和机制链。
- 只解释真正支撑结论的公式。

## 概念分段

- 一个概念写一段或一小节：先定义，再讲它解决什么问题，最后讲它和下一概念的关系。
- 同一段出现多个关键术语时，拆成多个小标题或短段。
- 英文术语首次重点出现时，附“英译中 / 怎么理解”。
- 抽象机制需要图解时，用小型 SVG 表达动作链或取舍关系。
- 一个标记回答只解释当前标记，不顺手解释整条机制链。

## SVG 图解触发

出现以下任一情况时默认作图：

- 需要解释三个以上步骤、角色、模块或变量。
- 有先后顺序、前置条件、失败链、取舍关系、预算分配或调度决策。
- 同一段出现多个技术对象并需要比较。
- 公式背后有分子、分母、约束或优化目标。
- 纯文字会超过两个自然段，或读者需要在脑中拼流程。

图只保留必要结构：

```text
输入 / 前提
  -> 关键动作
    -> 中间约束
      -> 输出 / 结果
```

- 图后必须写“这张图怎么读”。
- 图内文字保持简短，完整解释放在正文或读图提示中。
- 动作链、左右对照和变量关系按内容选择，不做装饰图。

## 自检

- 开头没有研究目的或只写“提升性能 / 提高效率”，重写到对象、瓶颈和收益。
- 缺少旧瓶颈到关键动作的因果链，重写。
- 文档式 HTML 缺少帮助建立全局理解的总览图，补图。
- 核心公式没有独立变量和直觉解释，补成公式组件。
- 同段堆叠三个以上关键术语，拆段或拆小标题。
- 关键英文术语没有“英译中 / 怎么理解”，补上。
- 稍复杂内容仍只靠长文字说明，补 SVG。
- 可见标题出现内部工作词，改成读者能懂的标题。
