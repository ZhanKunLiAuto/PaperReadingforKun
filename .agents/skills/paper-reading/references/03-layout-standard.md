# 论文 HTML 版式标准

## 目标

- 页面首先是一篇可连续阅读的精炼技术解读，篇幅与内容取舍遵循 `01-paper-method.md`。
- 正文是主层；划线协作、解释和个人评论是辅助层。
- SVG 是正文配图，不做装饰；适合的机制默认增强为可操作的 HTML 图解，遵循 `04-interactive-explainers.md`。静态回退与连续阅读不排斥机制交互。

## 首屏与阅读地图

- 首屏先出现一句研究目的，紧接核心判断与必要要点，图放在判断之后；不要让大图把核心结论挤到屏幕下方。
- 标题克制，副标题说明阅读对象和问题边界；不做营销 hero 或卡片仪表盘。
- 左侧阅读地图聚焦判断、方法、证据、边界与来源，通常 4–5 个主要入口；简短概念与背景可不单列导航，不因稳定 section 数量增加长章节。
- 空间不足时地图收起为左边缘浮窗。

## 版面

- `<1120px`：单栏阅读，批注与评论回到正文下方。
- `1180px-1499px`：左侧地图 + 正文 + 右侧协作栏，避免正文被挤压。
- `>=1500px`：增加留白，不拉长正文。
- 正文建议维持约 68–76 个中文字符的可读行宽。

## 批注与评论

- 同一条疑问和回答放进同一个 `paper-annotation`。
- `paper-question-marker` 小而明显；不显示原文、章节和时间戳。
- 正文高亮使用半高划线式背景，不做整行实心色块。
- `paper-comment` 是作者自己的观点、反驳、联想或待验证事项，与三类解释请求保持视觉和语义分离。
- 关联选区的评论紧跟锚点内容；整页或章节评论放入 `paper-comment-panel`。
- 已由 bridge 写回的评论属于 HTML 正文的一部分；浏览器本地评论必须清楚标示“仅此浏览器”。

## 概念与公式

- 一个正文段落只承担定义、机制、例子、边界或结论中的一个任务。
- 必要术语优先在首次出现处短释；确需独立解释时才使用 `term-bridge`，不把页面变成词典。
- 需要展示核心公式时使用独立 `formula-card`，包含公式本体、问题、所展示符号与关键约束的说明和直觉读法；不为使用组件而增加公式。
- 公式框宽度跟正文一致，不进入右侧协作栏。

## SVG

- 每个重要图使用 `svg-figure`；概念级小图使用 `svg-figure concept-visual`。
- 图只表达动作链、因果链、变量关系或取舍关系。
- 图后紧跟简短 `read-guide` 点明关键关系，避免正文和图注各复述一遍图中内容。
- 重组正文时，有用图保留为普通正文配图。

## 可访问性

- 正文、导航、按钮和输入框保持可见键盘焦点。
- 交互按钮提供明确文本或 `aria-label`，状态变化写入 `aria-live` 区域。
- 颜色不作为唯一状态线索；减少动画偏好时停用非必要过渡。
- SVG 提供 `role="img"`、`aria-labelledby` 或等价文字说明。

## 验证

- 修改后通过 localhost 用 Codex 内置浏览器刷新验证，不用 `file://` 替代。
- 新增或修改机制交互后，实际操作关键控件，检查图形与说明同步变化、入口可见且静态回退可读；不能只看首屏截图。
- 至少检查：新文案存在、目录锚点有效、批注与评论数量对齐、无重叠、主要断点可读、bridge 在线和离线状态可区分。
