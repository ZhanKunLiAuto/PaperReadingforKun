# 论文交互图解

## 选用与呈现

- 每篇先选最难理解、最影响核心判断的机制，通常只为其中 1–2 处设计交互；若文字或静态图已经清楚，就不添加。交互主题不等于新增章节，也不要求额外画一套总览图。
- 每个交互只回答一个具体问题，例如“训练和部署分别保留什么”“改变一个变量会怎样”“论文相对基线改在哪里”。选择最少的控件，避免把论文页做成仪表盘。
- 保持“静态图先讲清，交互按需展开”：默认正文和静态图可独立理解，交互入口放在对应机制旁边，可用折叠区按需展开。不要用大段折叠解释绕过精炼正文的要求。
- 优先在已有机制图上渐进增强。静态状态保留在 HTML 中，脚本未运行、加载失败或关闭交互后仍有有意义的图与说明；正文结论和必要证据不能依赖播放才能获得。

## 选择交互形式

| 理解难点 | 合适形式 | 必须看清的关系 |
| --- | --- | --- |
| 步骤、阶段或信息流 | 流程步进、阶段切换；按需播放一次数据流 | 当前输入、参与模块、输出，以及模块在训练与部署间的变化。 |
| 公式中变量的作用 | 拖动或输入一个关键变量，联动图形与数值 | 变量含义、合法范围、保持不变的条件，以及真实的数学关系。 |
| 方法改动或消融差异 | 在基线与论文方法间切换 | 使用一致的视角、布局和条件，突出新增、移除或改变的部分。 |

这些是选项，不要求每篇集齐。只有能减少理解负担时才组合；连续播放应可暂停，离散过程优先提供步进或重播。

## 证据与语义

- 图中的模块、方向、阶段和公式对应当次论文或官方实现，在附近给出实际使用的章节、图表或页码。箭头说明的是数据流、监督关系还是梯度流，不能混用。
- 明确标注简化假设和示意性质。玩具向量、插值动画或人为设置的参数不冒充作者实验；没有原文证据时，不把滑块值映射为成功率、性能提升或因果结论。
- 动画中的移动只表达所声称的过程。抽象特征传递不画成模型生成了真实未来；特征缓存、监督目标与推理输入应区分。具体结构由当次材料决定，不套用某篇论文的固定架构。
- 定量比较沿用原论文指标、单位、比较条件及不确定性；条件不同的结果不能通过切换造成公平对照的假象。

## 实现与协作兼容

- 在论文页使用可独立运行的 HTML、SVG 和 JavaScript；共享样式与交互放在仓库 `assets/`，只在需要的页面加载。复用现有能力，按实际复用需求抽取组件，不为一次交互建立框架。
- 发布后的交互在普通静态站点可运行，不依赖对话宿主的 `window.openai`、模型接口或本地 bridge。对话内的小样只有在用户要求写回时才迁入论文页；页面不包含 API key。
- 将动态更新限制在交互容器内，保留正文 section、稳定锚点、批注和个人评论，不重建整段正文。交互状态与协作标记分离；切换阶段不自动创建标记、评论或写回请求。
- 使用明确标签的原生按钮、滑块等控件，支持键盘和触屏。颜色不作为唯一线索；只对有意义的状态变化使用 `aria-live`，不逐帧播报。
- 默认静止，由读者触发运动；不持续自动循环。遵循 `prefers-reduced-motion`，关闭运动时仍可切换到完整、可读的结果状态。
- 按可用宽度重排图与控件，窄屏不靠缩小整张图来容纳文字，不依赖悬停才能读懂；遵循现有版式与 HTML 协作契约。

## 验证

- 逐一操作关键阶段、对比选项及参数边界，核对标签、图形、数值和说明同步更新；重复切换或重播不能叠加动画或留下旧状态。
- 经 localhost 检查桌面和手机窄屏布局、键盘操作、减少动画偏好与静态回退；确认脚本无报错，既有划线、评论和刷新定位仍可用。
- 真正新增或修改论文页时，执行 Skill 的页面验证和仓库发布流程；只修改这些规则时，检查引用、元数据和规则一致性即可，不把文档更新当作页面已实现或已发布。
