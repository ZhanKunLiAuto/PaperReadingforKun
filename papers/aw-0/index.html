WORLD MODELS · EVIDENCE & MECHANISMS

AW-0

让程序规划进入世界—动作模型，同时保留两种执行接口

Zhuoyang Liu 等2026-10-21 · arXiv v1

总体判断：AW-0 的贡献，是在视频—动作模型内部增加程序流，使可复用技能、控制逻辑和解释性注释能在去噪过程中约束未来预测与动作；又探索把同一程序直接执行的混合模式。真实双臂任务的平均 rubric 得分71.1%，明显高于所比较的46.0%最强基线，代码内容、视觉接口及注意力顺序消融也提供支持。但它并没有解决外观分布变化：RoboTwin random 默认20.6%，低于π0.5的27.7%；混合执行的仿真实验还换了示范来源。因此应将它视为有证据的程序引导控制框架，而非已具备在线自我进化的通用机器人 agent。[表1–4，附录I、L]

一个关键区别贯穿全文：默认推理生成程序但不执行程序，真正驱动机器人的是动作专家的动作块。程序通过内部注意力提供规划条件。只有额外的 hybrid 模式，才在检查通过时执行技能调用；两者不能混为“模型每次都运行自己写的代码”。

三种输出各自承担什么

输入包括当前多视角观察 Oₜ、指令 L、机器人状态 Sₜ，以及之前程序片段的压缩记忆 Mₜ。代码 C 表示参数化技能、基本动作调用与控制逻辑；视频潜变量 Z 表示未来视觉；动作 A 表示一定时域内的连续控制。模型学 p(C,Z,A|O,L,S,M)，把高层计划、预测未来与具体运动对齐到同一条示范。[式1–2]

以折叠毛巾为例，程序可以调用“夹住边缘、双臂移动、释放、叠放”等技能并保留先后顺序；视频流描述预期形变与终态，动作流输出手臂、夹爪目标。代码提供的是结构化语义，而非精确模拟布料的物理方程。它可以选对技能而给错参数，因此程序看起来合理不等于可靠执行。

在真机与预训练中，统一64维表示为左右各一组9维末端位姿、22维灵巧手关节、1维平行夹爪宽度；未使用的维度置零。动作位姿相对动作块首帧，手/夹爪目标为绝对量。RoboTwin 使用14维适配，不能把64维理解为所有评测共用的最终控制接口。[附录A]

外部编程与内部世界预测怎样互补

传统代码 agent 把感知和动作原语组合起来，但可调用的技能限制了控制精细度；WAM能生成连续动作与未来，却不一定拥有显式的技能复用和多阶段逻辑。AW-0选择把代码嵌入生成模型：它不必每次真的运行代码，也可借程序的结构组织低层预测。研究问题是这种规划条件有没有新增控制收益，而不是“代码天然比语言高级”。

自动标注用声明式原语 API、示范片段及接触/运动证据生成代码；协调器归纳跨任务重复模式。先形成并冻结技能库，再重标样本、建立片段缓存；其余数据匹配已有运动模式时复用，否则新增标签。预训练约2000小时YAM机器人与1000小时人类第一视角数据，两套技能库共50项（23+27）；因此技能来源依赖标注模型、接口设计和已有数据覆盖。[§2.3–2.4]

这套组合区别于在模型外再套一个自由编程 agent：代码流是经过监督训练的模态，和未来、动作一起生成；但技能库不会在部署时自动扩张，当前系统也不从自身交互在线更新参数。论文把持续学习列为后续方向，不能把愿景写成已有能力。[附录L]

代码先行的注意力与联合去噪

三专家有独立参数，也有明确的信息方向

三个专家各保留自己的注意力投影、归一化和FFN，每层在共同注意力空间交互。专家内部双向注意力，专家之间采用块因果顺序 C→V→A：视频能读代码，动作能读代码和视频；代码不反向读后两条生成流。因此“共同去噪”并不等于三者全双向互相反馈。[§2.1；图2]

代码专家以SDAR-1.7B的部分权重初始化并冻结这些部分，训练MoT投影和调制，使用冻结Qwen3-VL视觉塔而不是VAE作为视觉输入。视频专家以Cosmos-Predict2.5-2B初始化，替换为Wan2.2 VAE并重置接口；动作DiT从头初始化。三者28层，默认动作时域32，生成程序画布128 token，联合去噪4步。[附录A，表5–6]

离散程序与连续轨迹怎样在四步内一起形成

视频与动作以 xσ=(1−σ)x₀+σε 加噪，回归速度 ε−x₀；代码按独立掩码率把token替换成MASK，预测被掩码位置。每步提交最有信心的一部分程序token，同时推进视频与动作去噪。条件帧、指令与视觉前缀不被加噪。程序分布、动作噪声和视频噪声独立采样，推理时才共同推进。[式3–4]

原视频预训练偏高噪声，若动作一直看到接近纯噪声的未来，预测引导会弱。作者把视频采样分布与均匀分布按0.5混合，视频损失用原分布的重要性权重，动作/代码损失用均匀参考权重，截断并按batch归一化。这是在保护视频原目标与提供不同清晰度预测特征之间折中，不能简化成“所有模态共享同一个噪声”。[式5–6]

切换默认控制、混合控制和标注阶段，观察真正驱动机器人的路径。结构对应 §2.3、附录I；不执行真实机器人代码。

默认：代码只做内部计划

观察 + 指令 + 历史程序记忆
→
代码去掩码 C
↓ 引导视频 V
→
C + V → 动作专家 A
→
执行动作块
程序不执行

C→V→A 是 attention 可读方向，不是代码执行顺序；三流在同一迭代过程中更新。

混合：程序通过门槛才接管

同一模型输出程序 c + 动作块 a
→
阶段/依赖/语法/白名单检查
→
通过：技能原语执行 c
拒绝：执行 a
→
新观察后重新规划

只要尝试执行代码，本轮动作块就被丢弃；异常后也先重新观察，而非继续使用过时动作块。

记忆与仲裁的有限能力

之前生成的程序片段压缩为K个可学习记忆槽，作为代码前缀，避免当前画面无法辨认任务进度。训练时历史真值片段以一定概率替换为模型预测，部署每个episode重置。记忆保存计划历史，不是成功执行的完整可信账本。[§2.3]

混合模式依次检查阶段未完成/未倒退/失败次数未超限、引用变量存在、语法合法、调用白名单、非空操作等；不修复原生成代码。执行尝试标志不等于执行成功：出现异常也丢弃同轮动作块并下一轮重规划。附录算法以无异常作为阶段完成信号，尚无通用语义成功验证器；合法性仲裁也没有估计代码相对动作块的预期收益。[附录I，算法1–2]

默认模型用每任务50条clean示范训练，最高平均主要来自clean；random包含纹理、光照、桌高和干扰物变化，默认模型比自身clean下降60.2个百分点。hybrid在random高8.6点、clean低17.7点，但其训练使用另外收集的CaP程序生成示范，因此这是整套配置的比较，不能当作仅改执行开关的因果消融。[§3.1，表1]

真机：有多种子和细分任务，但指标是阶段得分

两种平台共8任务，每任务100条示范，3个训练种子×16次试验。平均rubric分数AW-0为71.1%，DreamZero46.0%、π0.5 43.6%；果物排列91.7%、翻记分牌68.8%、扑克58.3%等任务覆盖语义与精细接触。各任务按子步骤给分，不能把71.1%写成8任务全部完成率。Fold and Stack Towels使用同一后训练模型和条件比较，hybrid90.6对默认84.4，是比仿真更干净的执行模式对照，但仅一个YAM任务。[表2；附录E]

设计消融支持程序内容，而非所有模块都不可替代

代码视觉输入用ViT平均71.1，VAE55.6；程序联合去噪71.1，AR54.5，但换灯泡一项AR79.2高于75.0。去技能、去注释均下降，去技能后Deal Poker从58.3到42.0；完整程序超过自然语言子目标的任务数是7/8而非全部。注意力顺序C→V→A优于无代码及V→C→A，支持让规划参与未来生成。不过标签质量、token长度与预训练差异仍需在解释跨路线结果时保留。[图5、7；表3–4]

RTX5090上端到端推理为0.23秒，对AR0.55秒，约2.39倍；无代码为0.19秒，说明程序增加0.04秒约21.1%。计时包含视觉编码、联合去噪、视频解码和动作后处理，未等同于机器人运动或外部技能执行总时间。[图6；附录A]

程序可解析，不代表动作有保障

预训练验证中teacher-forced token准确率89.7%，自由生成解析率87.5%，但实体F1仅0.534、原语F1仅0.365；这些测量支持视觉条件化和语法学习，却表明语义及参数仍不可靠。论文展示正确选技能但位移参数多出元素的例子，说明必须分清“计划看起来对”“接口可执行”和“真实完成”。[附录F，表10]

代码自动标注与固定技能库限制长尾组合；视觉随机化也没有被代码规划消除。更有针对性的验证是保持训练示范完全不变比较两种执行模式，再添加显式执行进度校验、按预期优势选择代码或动作块，测失败恢复与错误调用代价。本文现有合法性门槛提供可用起点，尚不是最优仲裁或安全保证。

真机hybrid只在YAM检验，没有灵巧手对应CaP系统，跨平台混合执行因此尚未成立。AW-0也不在线学习。可以借鉴三条流的有向接口、用代码组织计划和保留动作后备；不应把生成代码能力、静态技能复用和终身自我改进混成同一个结论。
