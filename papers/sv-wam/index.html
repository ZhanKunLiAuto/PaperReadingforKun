PAPER NOTES · 2026.09

SV-WAM

六路环视保留，未来视频只在训练时提供监督

Jinyang Wang、Shiwei Li 等 15 位作者中科院自动化所、长安汽车等预印本 v1 · 23 页
研究目的

让世界模型驾驶规划器同时获得侧后方视野和更低推理延迟，避免六相机未来视频生成把部署成本推高。

核心判断

核心贡献是切断动作对未来视频的推理依赖，同时保留视频损失对共享参数的训练作用。它证明“预测未来”可以作为学习信号，而不必成为每次出动作前都执行的计算；但约 5B 参数、H20 上 342 ms 仍不能直接等同于车端实时部署。

先明确研究对象

世界动作模型（WAM）把未来场景和未来动作放进同一生成模型。这里的“动作”是车辆逐步的位移与航向变化，最终组成轨迹；“未来视频”是压缩后的视觉潜变量。论文主要研究规划与视频联合训练，并未以语言推理为核心。

原有瓶颈在哪里

许多视频世界模型规划器只保留前摄以降低开销，但变道、汇入和转弯需要侧后方信息。直接把未来生成扩成六视角会放大视觉 token 和去噪开销。SV-WAM 的选择是保留观测覆盖，减少推理阶段的生成任务。

非对称注意力，让动作能够独立生成

四帧历史六路图像与自车状态构成条件。训练时，Wan2.2-5B 的共享 Transformer 同时对未来动作和六视角视频潜变量做流匹配：从加噪样本学习如何还原轨迹和未来画面。（第 3–5 页）

最重要的不是训练后删分支，而是训练时就约束依赖。动作 token 只能读取条件与动作；未来视频 token 可以读取条件、动作和视频；条件本身也不能读取未来。这样既避免直接依赖，也堵住经条件 token 绕行的通路。作者报告有掩码时删除视频分支不改变规划结果。（图 4、表 4）

另一个设计直接针对出界：把预测轨迹送入可微车辆跟踪器，检查车身四角到可行驶区域边界的有符号距离，对接近或越界的角点加罚，并让较危险的时刻获得更大权重。地图约束只用于训练；附录说明作者把原本基于 NumPy 的跟踪与查询流程重写为 PyTorch，以便梯度传回动作模型。

表 1–3 支持训练监督和视野覆盖都有效，不能把相对其他单摄方法的全部增益都归因于新掩码。最终 91.0 高于表内 AutoDrive-P3 的 89.9，但六摄并非每项安全子指标都最好。

效率：同为六摄，两步推理，有掩码为 341.6±2.1 ms，无掩码需联合生成，为 848.0±1.8 ms；对应 EPDMS 为 91.0 与 87.3。计时在单张 H20、batch=1 下，从预处理完成的输入到轨迹输出，排除可选视频解码；这是一次受控对照，不是摄像头到执行器的总时延。（表 4–5）

迁移：仅在 NAVSIM 训练、直接评测 nuScenes 时，1/2/3 秒平均 L2 为 0.89 m，平均碰撞率 0.16%。这两项优于表 2 中零样本的 DriveVLA-W0 与 PWM；但对方只有前摄，且是跨数据集开环轨迹评测。

基准里的高分距离实车部署还有多远

闭环证据有限。NAVSIMv2 用预生成的合成观测做伪仿真，评估偏离专家轨迹后的恢复；它不同于长期、完整交互的实车闭环。论文明确把实车闭环测试列为未来工作，nuScenes 开环碰撞率也不能解释为真实道路事故率。（附录第 11、14 页）

训练与车端成本仍高。模型约 5B，两个训练阶段各约一天、各使用 16 张 H800。消除未来生成让推理显著变快，却没有证明低功耗车载平台上的延迟、吞吐和可靠性。

道路内行驶不等于所有行为都安全。软约束专门优化可行驶区边界，不能保证交互决策正确。作者展示了分叉左转选错路径、暴雨看不清信号，以及绿灯后过于保守而被追尾的失败案例。我的判断是：最值得复用的是训练监督与推理依赖的解耦，安全能力仍需更完整验证。
