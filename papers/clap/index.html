CROSS-EMBODIMENT · VIDEO WORLD MODEL · ACTION HARMONIZATION

CLAP

瓶子被推倒、毛巾被折叠、抽屉被拉开，物理规律不会因为执行者从人手换成 Franka、WidowX 或双臂机器人而改变；真正难的是，不同实体用完全不同的动作坐标，很多人类视频甚至没有动作标签。

Kechen Liu、Ola Shorinwa · equal contribution Princeton University arXiv v1 · 30 页
研究目的

把单一机器人、单一动作空间的 action-conditioned video model 推向跨机器人与人类视频混合训练：先找一种能在异构实体之间传递动作信息的共同接口，再把无标注视频中学到的动态先验落回真实机器人可执行的几何动作，使同一视频世界模型既能零样本参与真实机器人规划，也能作为少样本适配新实体的初始化。

核心结论

第一，CLAP 解决的是 action-conditioned video model 的“共同动作语法”。末端位姿把不同关节结构映成 7D 几何接口；语言动作把坐标写成文本；潜动作从帧间变化中自监督抽取 32D 代理动作。三者不是同一精度的等价编码，而是精度、标签需求与部署对齐之间的不同折中。

第二，最强配方 CLAP-CURR 不是把三种条件同时塞进模型。它先以潜动作从无标注视频学习时空先验，再替换成 7D end-effector action head，在有动作标签的视频上联合微调新 head 与视频骨干；部署时不再需要 latent-to-robot adapter。

第三，“接近或超过单实体 SOTA”在 DROID 成立得最强，在 Bridge 不成立。DROID 上 CLAP-CURR 的 PSNR、SSIM、LPIPS 略优于 Ctrl-World，但 FVD、FID 略差；Bridge-Base 则在五项指标上全部优于零样本 CLAP。论文自己的表格支持“有竞争力”，不支持普遍支配。

第四，标题中的 zero-shot physical simulator 要读成“零样本部署的视频预测器”。作者附录明确承认 CLAP 不能替代调好的物理仿真器、会幻觉且低于 10 Hz；真实规划还依赖 π0.5 / MolmoAct-2 生成候选、GPT-5 mini 评分，以及 end-effector→latent adapter。

READING OBJECT

“动作”在 CLAP 里有三种语言，zero-shot 也有三层含义

ACTION-CONDITIONED VIDEO WORLD MODEL（动作条件视频世界模型）

英译中：给定过去观测、任务语言与未来动作序列，生成这些动作可能导致的未来视频。

怎么理解：它不是直接输出机器人动作，而是充当“如果这么做，画面会怎样”的可学习预测器。CLAP 用它比较候选策略、给 RL 提供想象环境，或作为某个机器人专属视频模型的初始化。

END-EFFECTOR ACTION（末端执行器动作）

英译中：把关节位置通过 forward kinematics 转成末端的 x/y/z、roll/pitch/yaw 与连续夹爪状态，共 7 维。

怎么理解：它抹掉不同机器人关节数，但没有抹掉工作空间尺度。CLAP-EE 为每个平台使用独立归一化因子，把绝对动作压到 [−1,1]；因此所谓“统一”仍需要知道实体身份与运动学元数据。

LANGUAGE ACTION（语言动作）

英译中：把每帧末端坐标写成短模板，例如 x=、y=、z=、roll=、pitch=、yaw=、gripper。

怎么理解：文本接口容易接进预训练模型，但 CLIP tokenizer 不擅长保留高精度数字，长字符串还会截断。CLAP-LANG 因此采用相对动作、归一化和低精度模板，代价是空间分辨率低于连续 EE 条件。

LATENT ACTION（潜动作）

英译中：由相邻视频帧之间的变化自监督编码出的低维连续向量。

怎么理解：CLAP 的 LAM 读取 (fₜ,fₜ₊Δt)，输出 32D 向量，并尝试用 fₜ 与该向量重建未来帧。它让无动作标签的人类视频可用，却不等于真实机器人命令；真实规划中的 CLAP-LAM 仍需训练一个 EE→latent adapter。

ZERO-SHOT（零样本）

英译中：部署到目标真实任务时，不再用该任务数据微调视频世界模型。

怎么理解：这不是整个系统没有训练数据：世界模型已在 OXE / EgoDex 上训练，候选动作来自已训练的 π0.5 与 MolmoAct-2，VLM 负责奖励打分，CLAP-LAM 路径还使用动作对齐 adapter。论文另有 few-shot adaptation，属于超越 zero-shot 的另一设置。

PHYSICAL SIMULATOR（物理模拟器）

英译中：根据状态和动作预测未来演化的环境模型。

怎么理解：CLAP 输出像素视频，不显式计算接触、力、质量或约束。它可以作为政策筛选器和想象环境，但作者在附录 Q8 明确说目前还不能替代 well-tuned physics-based simulator。

FAILURE CHAIN

跨实体扩展不是简单把视频拼在一起：观察、动作与标签同时异构

“物理规律共享”是建模假设，不是从数据中直接验出的定律

瓶子、毛巾、抽屉的动力学确实不依赖操作者名字，但视频模型看到的是像素相关性：相机、背景、机械臂外观与任务分布都可能成为捷径。CLAP 的跨实体优势、held-out LAM 重建与 few-shot 迁移说明可迁移信息存在；它们没有分离出质量、摩擦、接触等显式物理量。因此“学到 generalizable physical priors”是有实验支持的解释，不等于模型识别了通用物理参数。

人类视频不是机器人视频的替代品

DreamDojo-Human 用仅在人类视频上训练的 IDM 抽潜动作；在 DROID 上 LPIPS 为 0.681，而 CLAP 各模型为 0.260 到 0.204，至少改善约 61%。论文据此认为人类视频可提供基础动态先验，但机器人视频对把先验迁到机器人形态至关重要。实际视频模型采样也高度偏向 DROID（附录 Table 3 报 75%），所以结果不是“只看互联网人类视频就会模拟机器人”。

绝对动作与相对动作没有跨表示的一致优胜者

EE 条件下，DROID 的绝对动作在 PSNR / SSIM / LPIPS / FVD 四项都更好，支持避免累积误差；语言条件下，相对动作把数值压进更紧范围，四项都优于绝对语言动作。但 Bridge 的 EE-relative SSIM 0.841 高于 absolute 0.822，OXE-Mix 的 EE-relative FVD 25.707 也略优于 absolute 26.199。论文“absolute across all metrics and environments”的文字比附录表更强，宜改读为“多数关键指标、尤其 DROID 上更稳”。

MECHANISM

核心不是一套新生成器，而是一条“潜动作扩展 → 几何动作落地”的训练链

世界模型回答的条件概率：给历史、任务和未来动作，生成未来观测

公式拆解 · Appendix Eq. 3
{oτ}t+Pτ=t+1 ∼ Vθ( · | l, {oτ}tτ=t−H, {aτ}t+Pτ=t )

这条公式回答：动作条件视频世界模型的输入与输出边界是什么。

l
任务层语言指令，例如“把鱼放进容器”。
H
历史 horizon；实现中使用 6 帧历史，以提供速度等时间线索。
P
未来预测 horizon；实现中生成 5 帧未来，窗口共 11 帧。
aτ
每一未来帧自己的动作 token，可来自 7D EE、模板语言或 32D latent action。
oτ
多视角 RGB 观测；CLAP 把各视角在 latent space 里垂直拼接。
模型不是从当前帧自由生成未来，而是比较“若执行候选动作 A / B，未来画面分别怎样”。历史解决速度歧义，逐帧动作条件提供可控性，多视角拼接提供几何约束。

潜动作模型：让视频自己给帧间变化命名

公式拆解 · Appendix Eq. 4
LLAM = ‖xt+1−x̂t+1‖²2 + β·DKL(N(μt,σ²t) ‖ N(0,I)),   β=10−6

这条公式回答：没有动作标签时，怎样迫使一个 32D latent token 携带从当前帧到下一帧的变化。

xₜ₊₁
真实未来帧；训练时输入帧对为 240×320 RGB。
x̂ₜ₊₁
解码器根据当前帧与潜动作重建的未来帧。
μₜ, σ²ₜ
潜动作后验的均值与方差。
β
很小的 KL 权重，明显偏向重建保真，同时让 latent 近似单位高斯。
若 latent 不包含帧间因果变化，解码器难以重建未来；但这个目标也可能编码相机运动、背景或非动作变化，所以“latent action”是代理表示，不是经验证的真实控制变量。

正文 Eq. 1 把同一目标写成 reconstruction log-likelihood 减 KL 的 ELBO 形式，适合最大化；附录 Eq. 4 写成 MSE 加 KL 的损失，适合最小化。两式方向不同但意图一致，页面采用更清晰的附录最小化形式。

CLAP-CURR：共享的是视频骨干，不是 action head

视频骨干：老 SVD、逐帧动作 token、历史与多视角拼接

CLAP 使用 SVD 的时空 U-Net：冻结 VAE 与 CLIP encoder，只训练 U-Net。每个 11 帧窗口含 6 帧 history 和 5 帧 future；每个生成帧只 cross-attend 自己对应的动作 token，而不是共享一个全局动作。EE / latent 由三层 SiLU MLP 映到 1024 维，语言动作由冻结 CLIP 编码。多视角先各缩放到 192×320，再垂直堆叠为 576×320；action context 以 5% 概率丢弃以支持 classifier-free guidance。

跨实体视频模型训练 100K steps，使用 8×H100 或 H200、effective batch 64，每次 run 约 2–3 天。附录默认推理写 50 个 EDM sampling steps；单独 timing benchmark 则用 25 steps、11 frames，二者不是同一配置。

真实规划：CLAP 不自产动作，而是在两位“提案者”之间做想象筛选

TECHNICAL DEBT & BOUNDARIES

CLAP 最扎实的是“动作接口 + 训练顺序”，最容易被标题放大的则是 simulator 与 zero-shot

第一，它不是物理引擎替代品

模型输出 RGB 视频，没有显式状态、碰撞约束、接触力、质量或摩擦参数；主要指标是 PSNR、SSIM、LPIPS、FVD、FID。附录 Q8 直接回答“not yet a replacement for well-tuned physics-based simulators”。“physical simulator”在本文中应理解为可供策略筛选的生成式像素预测器。

第二，它不是实时世界模型

11 帧、25 denoising steps 的 timing benchmark 为 A100 PCIe 3.24 s、A100 SXM 2.88 s、H200 1.49 s，远低于 10 Hz；冷 cache 的首次调用可约 15 s。模型占约 9.7 GB、低于 12 GB，可放进 RTX 3060 的显存，不等于在消费卡上实时运行。附录默认推理另写 50 steps，时间更不能直接套用。

第三，zero-shot 只限定视频模型没有目标任务微调

真实 planner 使用已训练的 π0.5 / MolmoAct-2 各提两条动作，GPT-5 mini 评价初末帧，CLAP-LAM 还需 EE→latent adapter。它证明跨实体 world model 可在不为该任务重训的情况下参与系统，而非“看一张图就独立产生新机器人技能”。

第四，实际训练规模远未到 internet scale

论文以“internet-scale capable”描述架构，但实际使用 OXE 与 EgoDex，视频模型 100K steps、8×H100/H200、每 run 2–3 天；附录 Q6 明确说规模远小于 GPT / Claude / Gemini。视频模型采样又以 DROID 75% 为主，因此跨实体收益与数据规模曲线仍未系统展示。

第五，最强 DROID 结论不代表跨所有域支配单实体模型

Bridge-Base 在零样本 Bridge 上五项指标全部优于 CLAP；作者附录 Q9 也明确说不会始终胜过单实体模型。DROID 的接近 / 超越很重要，但属于较困难、跨实体先验更可能帮助的目标域。

第六，感知指标不能完全验证动作与物理正确性

PSNR / SSIM 偏逐像素相似，LPIPS 偏感知距离，FVD / FID 看分布特征；它们可能奖励背景与外观，却错过夹爪是否抓牢、物体是否穿透、接触时序是否正确。作者担心 IDM / pose tracker 自身幻觉而未采用 object-centric 指标，这个理由合理，但留下了物理可用性评估缺口。

第七，CLAP 仍会在训练分布边界幻觉

结论与附录 Q11 都明确承认这一点；真实 planner 的唯一双臂失败是第二个物体掉在碗旁，且基础策略、视频预测与 reward 任一环节都可能出错。没有不确定性估计、拒绝机制或安全回退，尚不适合把生成轨迹当可信 rollout。

第八，few-shot / sample-efficient 缺少最关键的横轴

论文给出了微调后指标，却没有报告 DROID、Bridge、YAM、G1 各自用了多少 trajectory、帧、优化 steps，Table 14 新实体适配也没有 from-scratch / SVD baseline。因而可以说 CLAP 是有效初始化、能跨 7D→14D / 26D 适配；不能从现有表格计算样本效率。

第九，动作表示比较并非完全数据匹配

CLAP-LAM 可以加入 EgoDex 等无标签视频，而 EE / LANG 受限于有标签数据；作者认为强行 data-match 会违背框架目的。这适合回答“每种接口在最佳可用数据下能做到什么”，却不适合把性能差异全部归因于 action representation 本身。

第十，绝对 / 相对动作的文字结论比表格更绝对

DROID 的四项指标清楚支持 EE-absolute；但 Bridge 的 EE-relative SSIM 更高，OXE-Mix 的 EE-relative FVD 略低。更准确的总结是：连续 EE 多数情况下受益于绝对坐标和实体归一化，语言动作则稳定受益于相对坐标；不存在跨数据域、跨指标的严格全序。

第十一，双臂零样本仍是粗粒度压力测试

7D 模型每步只条件化动作幅度更大的手，把 14D 双臂问题降成动态选臂；这足以筛粗粒度进展，不代表模型同时精确模拟两臂耦合。95% 与“10 trials per task”的分母也不自洽，需要项目材料或复现实验澄清。

第十二，新骨干与更多实体仍是架构主张，不是实证

CLAP 使用 2023 年 SVD，因为每 run 约两天、可在消费级显存推理；附录称配方可无缝迁到 Wan 2.2 等新骨干，但没有实验。训练数据又主要是单臂机器人与人类视频；把双臂、humanoid、移动机器人加入预训练，是否继续带来正迁移仍待验证。
