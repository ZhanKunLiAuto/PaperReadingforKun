INTERACTIVE WORLD MODEL · CAUSAL VIDEO · LONG-HORIZON GENERATION

LingBot-World 2.0

Infinite Worlds with Versatile Interactions
从训练、交互到“无限世界”的证据边界

Zelin Gao 等 20 位作者 · Robbyant又名 LingBot-World-Infinity附件：arXiv v1 · 19 页
研究目的

让视频世界模型在持续接受用户动作时，长时间维持可用画质，并把操作扩展到开门、战斗和改变天气。

核心判断

贡献在于把抗退化训练、少步生成和语义交互组成可持续运行的系统。一小时演示支持长时视觉稳定，但尚未证明持久世界记忆；“无限”应理解为可继续生成的交互时域。[§3–6]

它生成的是动作条件视频

输入首帧、背景描述及不断到来的相机位姿和文字指令，模型按时间块生成后续画面。这里的“因果”首先是只看历史和当前输入，不能偷看未来指令；它不自动意味着模型学会了真实物理因果规律。[§3.1–3.2]

为什么越生成越容易坏？

训练时依赖干净的真实历史，运行时却接着自己生成的画面往下画：一次纹理或几何错误就可能变成下一步的条件。与此同时，多步去噪太慢，整段视频的单一描述也难以教会模型响应中途变化的指令。[§1–3]

先保住生成能力，再适应自己的误差

1. MoBA：让因果训练保留双向生成能力

作者观察到，纯 teacher forcing（用真实历史预测下一块）在长上下文下容易过度依赖历史，画质反而下降。MoBA 在训练注意力中并列加入双向分支：因果分支练逐块预测，双向分支保留整段去噪能力，作为正则约束。[§3.2、图 4]

两条分支的文本权限也分开。因果分支只读背景及截至当前块的描述；独立双向分支可读全局描述，不能把未来语义传给因果分支。数据端配套逐块标注，并去掉预告未来的措辞，使训练条件与在线交互对齐。[§2.3、§3.2]

2. 少步蒸馏：既要快，也要练习接着自己的结果生成

一致性蒸馏把教师多步去噪压缩成少步预测；随后用分布匹配蒸馏（DMD），将学生生成的分布推向教师估计的目标分布。关键是在学生自己的长轨迹上优化，让训练看到部署时会遇到的历史误差。这个机制针对误差累积，但本文没有用消融量化各部分贡献。[§3.3]

交互的扩展，来自模型外的语义组织

VLM 看当前画面，提出“开门”等事件，用户触发后将条件交给视频生成器；精细对象交互增加 SAM 跟踪。比如开门的文字后果可由 VLM 提议，门的运动仍由视频模型画出。语义上合理的提议，不保证碰撞与几何正确。[§4.2]

术语有一处不一致：摘要和引言将 pilot 称为规划角色行为的 agent，§4.2 与图 5 则把视频生成器叫作 Pilot。本页按后者的具体流程解读，不据此认定已有两个独立规划代理的完整实现。

因此，论文展示了方案可行，但“稳定性是结构性保证”“任意时长无漂移”“全面超过闭源模型”都强于现有证据。画面选帧也不能代替连续视频中的动作响应与物理一致性测量。[§5、图 10–12]

三个边界决定它能用来做什么

第一，持续生成还缺持久状态。作者承认，离开上下文的区域在重访时往往被重新生成，角色身份和风格也会漂移。动态 KV 缓存选择相关历史，缓解成本与干扰；它并未解决永久地图或对象记忆。[§4.3.2、§6]

第二，可见动作还缺可靠物理。模型从像素学习，没有显式几何和碰撞约束，会出现穿透。我的判断：它适合探索生成式交互，但要用于机器人训练或规划，还需验证动作后果、状态一致性及下游收益；本文未报告这些实验。[§6]

第三，模型开放与完整系统复现有距离。截至 2026-09-11，官方 README 已列出 14B 的三种变体和 1.3B fast，但明确不计划公开部署代码。480P 示例使用 14B/8 卡、1.3B/4 卡；这是示例配置，不是最低需求。摘要的“1.3B 单卡可部署”也未附同等输出规格的实测。[官方推理说明、部署说明]
