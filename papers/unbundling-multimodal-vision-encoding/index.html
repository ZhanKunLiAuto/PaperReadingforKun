Unbundling Multimodal Vision Encoding

视觉编码器的哪一部分值得保留？

把“先学视觉”“给图像留参数”和“先编码再融合”拆开检验

Ellis Brown、Chris Hoang 等Meta FAIR · 纽约大学2026 年 11 月预印本
总体判断

在同一图像池、同一笔训练算力下，最值得保留的是早期只服务于图像的计算。一个随机初始化的视觉 Transformer 可以和多模态主干一起学，做到与先单独预训练相近的视觉问答成绩。进一步，把相近数量的视觉专用参数搬进主干前几层，成绩仍然接近。直接删掉这部分容量，再把同样多的参数平摊给图文，视觉问答会落后，读文字和图表尤其明显。结论的力度来自受控比较，适用范围也随比较条件而定。

长训练下，1.7B 主干配前置视觉编码器得 48.9 分，配主干内视觉分支得 49.2，仅做图块投影得 44.8。到 4B，三者是 54.5、54.3、51.7。视觉计算放在主干内外的名次互换，移除它的代价却在两档规模都存在。这比单独引用最高分更能说明论文的贡献。〔表 26〕

跟着一个图块，看“编码”到底发生在哪里

设想给模型看一张柱状图，问“五月的销量是多少？”它要读出月份和刻度，找到对应柱子，再把数值写成答案。这个例子用来解释计算路径；论文报告的是整组图表与文字识别任务的成绩。预训练时，一张 224 × 224 图像切成边长 14 像素的图块，排成 16 × 16 的网格，即 256 个视觉 token。图块只是带位置的一块像素，一个图块可能只包含半个数字。

常规的前置编码器让这 256 个位置先通过只处理图像的网络，汇集其他位置的信息，然后线性投影到语言主干的向量维度。直接投影则把各图块线性映射，加入位置信息，经归一化与可学习标量门控就送入主干。它仍有输入映射，也能在主干里聚合图块；论文所说的 encoder-free，指省去了那一大块视觉专用计算。〔§2.1、附录 A.1〕

融合边界是图文 token 第一次可以相互建立注意力关系的层。这里仍遵守序列掩码：同一图中的图块可以双向聚合，后面的文本可以读取前方图像和文本。模型只对文本位置计算预测下一个 token 的损失。当它根据柱子和刻度生成答案时，文本损失的梯度能沿注意力路径回到视觉参数；视觉分支由此获得与下游语言输出相关的训练信号。〔§2.1、式 2–3〕

比较两种架构，先算清它们各自花掉的 FLOPs

直接比较两个已发布模型时，其中一个可能用过规模庞大的图文对齐预训练，另一个可能用了更好的描述、更高分辨率或更长的训练。即使最后问答分数不同，也难以把差异归给编码器。作者自训所有对照组件，包括仿 Qwen3 的稠密语言主干。主实验用 1.7B 和 4B 主干，前置视觉网络采用同一款 27 层、约 0.4B 参数的 ViT。〔§2、表 4〕

全程训练算力把上游视觉预训练、可能存在的纯文本预训练、多模态训练相加。固定这笔 FLOPs，架构每处理一个 token 的成本不同，实际读到的 token 数也会不同。论文中的 token-equivalents 是“相同算力够同规模纯文本模型处理多少 token”的换算量。比如 1.11T 指预算等价量，不能解读为各模型都看到相同的 1.11 万亿个训练 token。后文的 TPP 是把等价 token 数除以主干的非嵌入参数数。统一的下游指令微调单列在预算外。〔式 1、表 12〕

多模态阶段按序列数混合 70% 纯文本与 30% 图文，图文来自英文 MetaCLIP 1.2，统一使用 Qwen2.5-VL-32B 重写的描述。上游编码器使用同一图像池，涉及文字的上游目标默认使用原始网页替代文本。相同数据来源控制了“哪组多拿一套图片”，没有强求所有阶段见过完全相同的文本、样本次数或 token。〔§2.2、附录 A.4〕

论文有两把尺。Avg. VQA 在 Cambrian-7M 上做三轮统一指令微调，默认把图像提到 448 × 448（1,024 个视觉 token），再等权汇总通用问答、知识、OCR 与图表、视觉感知四类共 16 项基准。Avg. Text 直接评估指令微调前的主训练检查点，将 12 项语言基准先按四类求均值，再平均。两列分数刻画的是各自协议下的能力。〔§2.5、附录 B.1–B.3〕

保留图文共享计算，同时给图块一条额外路径

四种配方沿着三个问题排列。预训练 ViT 先单独学视觉，再接入主干联合更新。从零 ViT 保持完全相同的前置结构，从第一步就跟主干一起优化。直接投影 让图块尽早进入全共享网络。融合内分支（in-fusion） 也让图块从第一层进入主干，但在早期层给视觉 token 增加专用权重。由此，可以先比较“先学过没有”，再比较“视觉参数该留多少、放在哪里”。〔图 1、表 1、图 4〕

一个视觉 token 在早期层中究竟多算了什么？

融合内路由 · 式 2–3

P(z) = WPz + m · ΔWPz

h′ = h + F(N(h)) + m · ΔF(N(h))

每个位置都经过共享投影和共享前馈网络。m 由该位置的模态直接确定，图块为 1，文本为 0。

第一式用于 Q、K、V、O 四个注意力投影。z 是相应投影的输入。第二式中 h 是残差流，N 是归一化，F 和 ΔF 同时读取归一化后的 h。图块取两条分支之和，文字只走共享分支。

以图中某个刻度为例，它的 key 和 value 可以带上视觉专用投影的修正，后续提问里的文字仍用共享 query 在同一次注意力计算中读取它。模型无需为图文再做第二次独立注意力，也无需学习一个路由器来猜 token 的模态。额外注意力投影和视觉 FFN 的输出投影都从零初始化，训练开始时额外路径的贡献为零，之后可随文本监督逐渐学出作用。纯文本请求跳过视觉分支，但联合训练仍会更新共享权重。〔§5.1、附录 E.1〕

论文还有一个 FFN-only 变体，只添加视觉前馈分支。它让作者先固定约 0.4B 的额外参数，集中检验加在哪几层，随后再问给注意力分配一部分预算有无帮助。另一个对照 MoT 为不同模态分别使用一套权重；融合内方案保留每个图像 token 经过共享权重的路径。〔图 4–5、表 23、25〕

三组对照，分别回答先验、专用容量和位置

一、视觉必须先单独学吗？

固定 1.7B 主干和 1.04 × 10²² FLOPs 总预算，拿出约 15% 先训练同一款视觉编码器。整机的 Avg. VQA 分别是：从零联合训练 49.0，图文对比学习 MetaCLIP 47.5，视觉自监督 WebSSL 49.3，两种描述生成目标 Cap 与 CapPa 为 48.3、47.2。把 MetaCLIP 冻住则得 45.5。WebSSL 在视觉感知类高于从零训练（55.5 对 51.1），在 OCR 与图表类低于它（39.8 对 43.4）。上游目标能改变擅长的任务，但这组结果没有给出稳定的平均问答优势。〔图 2、表 16〕

也可能只是预训练挤占了联合训练预算。作者因此固定多模态阶段为 2.7 × 10²¹ FLOPs，把 MetaCLIP 上游计算当成免费。上游从 1.4 增到 9.0 × 10²¹ FLOPs 时，冻结编码器的 ImageNet 线性探针准确率从 80.4% 升到 84.4%，整机 Avg. VQA 两个端点却是 43.2 和 41.6，从零训练为 43.5。一个表征让线性分类器更容易认出物体，不足以预测它能否为语言模型保留问答需要的细节。〔图 8、表 18〕

三、为什么强调早层，而且只给图像？

在同一 1.7B 主干、同一 0.4B 预算下，作者只移动额外视觉 FFN。放在 28 层中的前 8 层得 45.0；放到末 8 层得 35.1，均匀选 8 层得 37.6，拆窄铺遍全部层得 39.4。再固定前 8 层，允许所有 token 都用额外分支得 42.3，单纯加宽共享 FFN 得 40.1。前置 ViT 在这笔预算下为 44.4。这组对照同时说明，靠近原始图块、集中参数、限定服务对象都会影响结果。〔表 3〕

一种合理解释是，图块在早层要把分散的字形、边缘和布局组织成后面可读的特征。更晚才投入专用计算，后续层利用这些特征的机会也变少。作者观察到融合内模型的视觉表示在早层变化较大，经过专用层后趋于稳定；直接投影模型的变化延伸到更多共享层。探针提供了与解释一致的观察，无法单凭这些变化确定模型学到了哪种字形算法。前 8 层是主消融找到的配置，更大主干的缩放实验会调整层数。〔附录 E.4、G〕

换主干、延长训练，或者从已训练好的语言模型开始

在 1.11T token-equivalents 的长预算下，从零 ViT、融合内完整分支和直接投影分别取得开篇列出的两组三个数字。1.7B 的融合内分支领先前置 ViT 0.3 点，4B 时落后 0.2 点。更短预算下二者可以拉开距离，例如 4B 的 31 TPP 对照中，前置为 47.8、融合内为 45.5。“接近”描述长预算结果和整体趋势，各个检查点仍有差别。〔图 6、表 26–27〕

作者还单独训练了 0.6B 到 6.4B 的五档主干，视觉参数随主干一起扩展，并用模型规模和等价 token 数拟合 VQA。以其中 1.7B 至 6.4B 各档的 64 TPP 为参考点，拟合曲线估计，直接投影达到前置 ViT 同一 VQA 需要 2.6–3.1 倍训练 FLOPs，融合内约为 1.0–1.1 倍。纯文本损失的相应倍数都约为 1.0。这是特定拟合与参考点的等性能估计，不能直接换算为 GPU 小时或外推到更大模型。〔图 7、表 29–31〕

更常见的工程起点是已经有一个语言模型。作者先用 1T 纯文本 token 训练 1.7B 主干，再继续训练至 1.33T 等价 token。融合内、从零 ViT、直接投影和免费 MetaCLIP 的 Avg. VQA 为 50.1、48.6、39.8、43.5。只复制前八层给视觉用的 MoT 达 48.5，复制全部层虽有 1.41B 视觉专用参数，却只有 43.3。即使起点是语言主干，早层视觉专用路径仍有价值；这项验证使用的是作者自训的一款底座。〔图 9、表 33–34〕

移进主干，换来的是多久看到第一个输出 token

一块 H200 上同时处理 16 个请求，每个请求有一张 448 × 448 图和 256 个文本 token。1.7B 主干配约 401M 视觉参数，前置 ViT 的首 token 延迟为 210 ms，完整融合内分支为 182 ms，仅 FFN 为 171 ms，对应约 13% 和 18% 的下降。直接投影最快，为 146 ms，但长预算 VQA 也最低。4B 的前置与完整融合内分别为 405 和 381 ms，降幅约 6%。〔图 10、表 26、36〕

前置 ViT 先跑完一串较深的图像层，主干才能开始。融合内方案把视觉计算安排在较少、更宽的早层，缩短了这段串行路径。作者在同一套 eager 执行实现上取四次测量的中位数。首 token 之后的逐字生成、端到端完成时间，以及混合纯文本和图文请求时的连续批处理，都有各自的瓶颈；用这里的 13% 给所有请求估算加速会高估证据。〔§6.3、附录 H.3〕

两组能追平的对照，给“需要视觉容量”划出边界

共享计算花得更多，也能追上。附表 20 固定实际训练 token 数和恒定学习率，把预算约束放松。共享 FFN 增加 0.8B 参数、使用 6.3 × 10²¹ FLOPs，VQA 得 44.4；前置 ViT 增加 0.4B 参数、使用 4.7 × 10²¹ FLOPs，得 44.2。在这个设置里，专用计算提高的是达到相近分数的效率。直接投影模型完全可以通过更多共享资源学到有效视觉表示。〔附录 D.2、表 20〕

每个视觉 token 看见多少像素，也会改写结果。附表 21 固定输出 256 个视觉 token，使用该表的低分辨率指令微调协议。约 44M 的四层层次 MLP 将 640 × 640 输入逐级压缩成 16 × 16 网格，得到 40.2，与吃 224 × 224 输入的 401M 前置 ViT 持平；标准 224 输入的直接投影只有 36.9。OCR 与图表三者分别为 26.7、26.9、17.5。这组结果同时改了输入细节和压缩方式；MLP 自身也承担视觉专用计算。它说明轻量前端加高分辨率是一条可行路径，同像素、同 token 下应另行比较。〔附录 D.3、表 21〕

“视觉理解”在本文主要通过问答来测。在为图像匹配正确描述和困难负例的 SugarCrepe 对照上，多种方案的替换与交换子集均分接近。同图像池训练也特意排除了现成编码器带入额外数据知识的优势。结论最稳的范围，是以图像描述和文本训练的稠密主干，再经指令微调测静态图像问答。对超大稀疏 MoE、视频、多图交错、文字密集图像预训练，或直接采用已在更广数据上训练的编码器，这些实验都尚未给出同条件答案。〔表 17、§8〕
