FlashVLA、CLAP、Riemann-1.0、BrainWAM、Zero-WAM 与 Code as Worlds：当模型既要行动，也要理解行动的后果。

中文横向导读6 篇研究 · 4 张比较表 · 3 张关系图研究脉络按问题组织，不按发表时间排序
研究目的

把六篇工作放在同一张问题地图上：机器人怎样及时执行动作，怎样预见后果，怎样借用人类经验，以及怎样检验自己想象的世界。读完应能分清每篇补了哪一块能力、付出什么代价，并据此选择精读对象和研究切入点。

核心结论

第一，六篇并不是六个同类 WAM。FlashVLA 是 VLA 解码与调度方案；CLAP 是外接动作条件视频模型；Riemann、BrainWAM、Zero-WAM 用不同接口连接世界预测与行动；Code as Worlds 是可执行世界发现与物理监督路线。

第二，关键分歧是信息以什么形式、按什么顺序进入动作决策。动作先于视频、视频先于动作、两条通路先各自形成动作，这三种设计会产生不同的延迟、信息瓶颈和误差传播路径。

第三，世界预测有用，不等于世界已经正确。控制成功率、视频相似度、驾驶规划分和物理量问答各自只检验部分能力。六篇合起来最值得追问的是：在统一预算下，更准确的行动后果预测，能否稳定改善真实闭环决策？

比较范围：本文以仓库六篇解读为主要材料，沿用其锁定的论文版本；数值是各论文报告值，没有重新复现实验。“研究脉络”“互补关系”和后续实验建议是本导读的综合分析。所有简称均可通过表格中的论文名返回单篇解读。

ALIGN THE OBJECTS

先对齐三个词：任务、动作、世界

VLA / WAM · 视觉语言动作 / 世界动作模型

怎么理解：VLA 通常从视觉与任务指令预测动作；显式世界预测进一步问“执行以后会看到什么”。WAM 在这些材料中指把行动与未来建模联系起来的一类方法，并没有唯一架构：可以共享骨干，也可以分支协作或先预测视频再推断动作。

ACTION REPRESENTATION · 动作表示

避免误读：可执行控制量、用于预训练的潜动作、网络内部的 action token 不是同一层对象。潜动作从帧间变化中学出，不一定能直接驱动机器人；BrainWAM 的 action token 是协调特征，最终输出才是驾驶路点。

后文三个模块缩写可先记住功能：BrainWAM 的 CAB 是两路动作特征的双向交流模块，CIF 负责最终融合；Zero-WAM 的 IFP 是仅训练时使用的远期视频预测监督。它们分别处理信息协调和任务信息保留。

Code as Worlds从文本 / 视频发现世界程序，生成物理监督；下游 VLM 回答物理标量与单位。机器人控制动作不适用。程序描述初态、运动轨迹，或力、接触与约束。EWR（可执行世界表示）：结构、演化、外观分离；经引擎模拟与渲染检验。不是机器人策略。

这里至少有四种“世界”：CLAP 的可见未来，Riemann / Zero-WAM 中与行动相连的视频过程，BrainWAM 中有助规划的预测特征，以及 Code as Worlds 中能编译、模拟和测量的结构化程序。它们有交集，但不能只凭名字互换。

A RESEARCH THREAD, NOT A TIMELINE

从 VLA 出发：每补一种能力，就暴露下一个瓶颈

1 · 会选动作，还要赶得上执行

大模型策略即使预测准确，等待完整去噪仍会让机器人使用过时信息，异步执行又可能造成新旧动作不连续。FlashVLA把完整动作块去噪拆进流水线，缓存中同时保留不同成熟度的动作块，使后续动作能看见正在执行的计划。它改善了“何时交付动作”，并没有因此获得外部世界预测能力。

2 · 动作能及时交付，选之前能否看一眼后果？

CLAP把问题转为动作条件视频预测：先让已有策略提出候选，再想象不同候选的结果。瓶颈随之从动作解码转向跨本体动作条件对齐、未来视频可信度和生成开销。预测器能够筛选动作，但仍需有人提出候选、判断哪个后果更好。

3 · 把动作与世界放进模型，接口应怎样组织？

Riemann-1.0选择统一时序：先动作、后视觉后果；同一骨干在策略模式接收真实反馈，在模拟模式回灌预测视觉。BrainWAM选择专业分工：语义与动力学各自产生动作表示，再协调。前者回答“生成顺序如何统一”，后者回答“知识通路如何互补”，二者不是必然的替代关系。

4 · 数据与任务怎样超出已有机器人示范？

CLAP 和 Riemann 借潜动作吸收更广的人类或异构视频经验；Zero-WAM进一步把人类示范放进测试时上下文，让它指示新任务的未来过程。这里的难题是：模型是否真正读取示范中的任务信息，还是只靠机器人历史和语言就完成训练目标？Zero-WAM 用远期预测压力处理这条信息捷径。

5 · 未来看起来合理，如何检查内部机制？

Code as Worlds把隐含世界改成可执行程序，让世界假设经过模拟与观测比对，并产生可测量的监督。它为“怎样审查或训练物理理解”提供支线，但现有实验没有把这个循环接进机器人策略，也没有证明从单段视频能唯一恢复真实因果机制。

这条脉络的含义：VLA → world-action model 是从“预测动作”扩展到“连接动作、后果与经验”的问题扩展。本文连线是帮助阅读的概念组织；六篇没有共同训练、统一评测或逐篇继承的证据。

INTERFACES & DATA

最关键的设计：谁先预测，信息经过哪里？

公式读法 · 用统一记号比较信息方向
动作优先（Riemann 的顺序抽象）
p(a, o⁺ | H, g) = p(a | H, g) · p(o⁺ | H, g, a)
视频优先（Zero-WAM 的信息瓶颈）
p(o⁺, a | H, h, g) = p(o⁺ | H, h, g) · p(a | H, o⁺, g)

这组公式比较“预测一个动作块及其未来视觉”时的条件分解；是本文统一记号后的机制摘要，不是六篇共享的训练目标。

H / g
H 表示模型可用的历史上下文，g 表示语言或任务条件。各论文的具体历史模态不同。
a / o⁺
a 是下一动作块，o⁺ 是相应未来视觉块；p 是条件分布，不是成功率指标。
h
人类提示视频。Zero-WAM 的第二项不直接读 h，而通过 o⁺ 接收其信息；这包含架构施加的条件独立假设。
乘法顺序揭示了接口代价：一边先决定怎么动、再想象后果；另一边先确定未来该发生什么、再反推动作。Zero-WAM 训练时动作分支读真实未来、推理时读生成未来，因此还存在训练与推理输入不一致的问题。

三种“借人类经验”的方式尤其值得分开：CLAP / Riemann 把人类视频作为预训练经验，Zero-WAM 还把人类视频作为测试时任务提示，Code as Worlds 把世界发现结果转成量化监督。它们分别扩大训练分布、改变任务输入、改变监督形式。

WHAT THE EXPERIMENTS ESTABLISH

评测证据：成功率高，究竟证明了哪种能力？

三个容易误读的“领先”

同名 benchmark 不保证同一协议。FlashVLA 与 Riemann 都报 LIBERO、RoboTwin，但骨干、数据量、任务拆分、训练和计时配置不同。现有材料不足以把 99.0% 与 97.8% 的差直接解释为“WAM 比 VLA 好多少”。

组件收益与系统收益要分开。CLAP 的真实规划将两个策略的四个候选交给世界模型与奖励器筛选，90% 是系统结果；BrainWAM 的同骨干内部消融则更接近验证融合接口的作用。注意力图可支持解释，但仍不是严格的因果干预证明。

指标名字里都有“准确”，含义也未必相同。SR 是任务完成比例，PSR 衡量任务进度，PDMS / EPDMS 是驾驶规划综合分，MRA 是多个相对误差阈值上的准确率均值。它们没有共同分母，不应平均成“六篇总体能力分”。

THE OPEN RESEARCH GAP

六篇共同留下的缺口：预测怎样可靠地改善行动？

把“可能互补”变成可检验的研究假设

假设一：世界预测需要自己的调度策略。FlashVLA 的分层缓冲和 BrainWAM 的视频提前停止都提示，并非每个输出都要同频、同精度更新。值得测试的是，在固定硬件与端到端预算下，怎样分配预测和动作算力。六篇没有证明 FlashVLA 已能直接接入任一 WAM；首先要验证接口兼容性与闭环误差。

假设二：共享视觉未来可以转移任务，但也会传递错误。Zero-WAM 用视频连接人类示范与机器人动作，CLAP / Riemann 用潜动作连接异构经验。下一步可固定数据与骨干，分别改变示范提示、潜动作对齐及真值 / 生成未来条件，测量任务泛化和误差传播，而不是只比较最终成功率。

假设三：可执行世界可成为预测器的检查工具。Code as Worlds 提供结构化参数和模拟接口，可能用于构造“同一状态、不同动作”的对照监督。但这仍是研究建议：动画式轨迹拟合与由力、约束驱动的物理模拟需要分开评估，且必须检验引擎误差、观测不可辨识和真实接触情形。

读“零样本”和“世界模型”时保留的边界

CLAP 的零样本是目标任务未对世界模型微调；Zero-WAM 是任务留出后的上下文泛化；Riemann 的另一组 held-out 实验是同平台四任务、各 10 次的 30/40 成功。它们都不能自动推出“无需机器人数据的新本体零样本控制”。

同样，动作条件视频看起来合理、内部特征能提高规划分、程序能重放观测，分别只是世界建模的一部分。是否具备稳定的反事实预测、长期一致性、误差校准以及低延迟纠错能力，还需要专门实验。
