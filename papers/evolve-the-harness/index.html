FIXED MODEL · EVOLVED HARNESS · STRICT VERIFIER

别急着训练模型
先让 Harness 进化

一个在法律代理任务上端到端成功率为零的开放模型，也许不是不会做法律工作，而是被文件路径、工具调用、终止条件和评测接口拖成了零分。这篇文章把这个猜想变成了一次自动化搜索实验。

Joel Niklaus · Hugging Face 发布于 2026-07-01 研究文章 / 实验报告 · 26 页 PDF
研究目的

检验一个成本更低、也更容易被忽略的能力提升路径：冻结 DeepSeek-V4-Pro 的全部权重，让自动化循环只改写模型外围的运行支架（harness），看它能否把“已经做对但没有正确交付”的潜在能力转化为 Legal Agent Benchmark 可识别的结果，并测量这些改动能否在留出测试集和其他模型上继续成立。

核心结论

第一，Agent benchmark 测到的是“模型 × Harness × 评测协议”的联合系统，不是裸模型。在相同模型、相同 100 题留出集和相同 judge 下，不同支架的 pooled criterion pass rate 从 3.5% 到 80.1%，说明外围系统足以改写我们对模型强弱的判断。

第二，最大收益来自确定性代码，而不是更花哨的提示词。把最终文件放到正确目录、使用精确文件名、修复损坏的 tool call、打断重复循环、核对是否写错案件，这些动作不增加模型知识，却能把“完成了但不可见”变成可评分结果。

第三，自动化搜索的真正核心是 verifier。提议模型可以自由提出机制，但固定开发集、三次重复、混合得分和晋升门槛决定什么会被保留。目标函数一旦有偏，循环只会更高效地放大偏差。

第四，这不是“以后不用训练模型”。优化在约 83% 的 dev pooled rate 附近进入平台期；Section 382 税务任务仍稳定缺失定量深度和引用精度。支架能修执行层，不能凭空生成基础模型没有掌握的实体知识与推理能力。

MODEL, HARNESS, AND META-HARNESS

先把三个角色拆开，否则很容易误读实验

HARNESS（运行支架 / 执行外壳）

英译中：围绕基础模型的一层运行时系统，负责给模型哪些文档、哪些工具和哪些上下文，执行 tool call，并决定何时结束。

怎么理解：模型像发动机，harness 像变速箱、仪表盘、导航和刹车。发动机不变，车辆仍可能因为传动方式不同而表现悬殊。本文搜索的对象正是这层代码与系统提示。

两个指标回答不同问题

Pooled criterion pass rate（汇总标准通过率）把所有任务的 rubric 条目放在一起，计算通过比例。它稠密、平滑，适合做优化信号；但一个任务只过 90% 标准仍可能无法交付。

All-pass rate（整题全通过率）要求某个任务的每一条 rubric 都通过，才算端到端成功。这是 LAB 的 headline metric，也更接近真实交付，但在 24 题 dev set 上极其稀疏，直接优化很容易追逐偶然性。

MISMANAGED GENIUSES（被管理失当的天才）

英译中：模型本身拥有一部分完成任务的能力，却被脆弱的外围系统限制，导致评测把“支架失误”错误归因给“模型不会”。

避免误解：这个假说不等于模型已经具备全部专业能力。本文最强证据只说明 vanilla harness 严重低估了可兑现能力；平台期和残余错误同时说明基础模型仍是硬约束。

WHY ZERO CAN BE MISLEADING

旧瓶颈：法律推理做对了，交付链仍能把它归零

LAB 的任务不是选择题，而是封闭工作区里的真实法律事项：阅读合同、邮件、表格和幻灯片，最后产出尽调备忘录、问题清单、修订稿或合同草案。Judge 只读取 output/ 顶层、且文件名匹配要求的交付物。于是“写得好”和“被评分系统看见”是两件事。

同一个模型，换一层外壳，分数能差 76.6 个百分点

在相同留出集和相同 judge 下，优化后的 LAB harness 得到 80.1%，stock LAB 为 63.4%，Pi 为 45.4%，Goose 为 23.2%，mini-swe-agent 只有 3.5%。这组对照最直接地说明：Agent 分数不是模型的单变量属性。

为什么不用手工一点点修

手工 harness engineering 需要人反复看失败轨迹、提出假设、写补丁、重跑昂贵评测，而且修法往往依赖具体模型。Meta-Harness 把这个循环自动化：让语言模型充当研究员，让普通 Python 程序充当严格实验室。

COPY, ADAPT, EVALUATE, PROMOTE

进化循环：一次只加一个机制，让胜利可以累积

为什么坚持“一次只改一个机制”

候选从当前最佳 harness 精确复制，再增加一个改动。这样一旦得分上升，就更容易把变化归因到具体机制；晋升后，后续候选继续继承它。作者把假设、改动、预期修复任务、回归任务和观察证据写入 pending_eval.json，让搜索历史可追溯。

晋升分数拆解
S = P + 0.5A - 0.005T

这条公式回答：一个候选是否比当前最佳更值得保留？候选还必须满足 Scandidate − Sincumbent ≥ 0.01。

S
混合晋升分数。越大越好，但它只是搜索目标，不是 LAB 的最终 headline 指标。
P
Pooled criterion pass rate。稠密、平滑，是主要优化信号。
A
All-pass rate。乘 0.5 作为奖励：端到端完成值得加分，但单次幸运成功不足以独自跨过 1 分门槛。
T
每次运行消耗的百万 token 数。系数 0.005 相当于每百万 token 约扣 0.5 个百分点，避免昂贵候选靠很小收益晋升。
直觉读法：先看它是否让更多评分标准稳定通过，再奖励整题完成，同时对额外 token 收税。真正关键不是公式长什么样，而是 challenger 与 incumbent 必须在同一组权重下重新计算；论文附录展示了使用陈旧 incumbent 分数会错误晋升一个全面更差的 harness。

三次试验是在花钱买“可晋升的信号”

单次完整 pass 的 pooled rate 分别为 72.9%、76.2% 和 74.9%，标准差约 1.4 个百分点；除以 √3 后，三次平均的噪声约 0.8 点，略低于 1 点晋升门槛。总体均值看似稳定，但个别任务会因 provider 错误或缺失交付物突然跌到 0%，足以在小 dev set 上翻转决策。

WHAT THE RESULTS ACTUALLY SUPPORT

证据链：成绩确实大涨，但“涨在哪里”比总分更重要

比较 数据 Pooled criterion All-pass 能支持的结论
Vanilla → final frontier 24-task dev，候选各 3 trials 63.1% → 83.3%（+20.2pp） 0% → 4.2% 搜索能在开发分布上持续累积收益
Vanilla → final frontier 100-task held-out test 63.4% → 80.1%（+16.7pp） 0% → 5.0% 开发集收益大体迁移到未见任务
Deliverable landing gate 24-task dev 72.8% → 79.2%（+6.4pp） 文章未单列该步变化 单个确定性交付修复贡献了最大跳升
同模型，不同通用 harness 100-task held-out test Pi 45.4 / Goose 23.2 / mini-swe 3.5 均为 0% Harness 选择本身是强混杂变量

最强改动不是“让模型更聪明”，而是把已有工作交出去

deliverable_landing_gate 在模型结束后检查声明的交付物，把正确文件放到 grader 读取的顶层目录并使用精确名称。它不增加模型 token，却让 dev pooled rate 一步上升 6.4 点。这是全文最干净的因果故事：改动直接命中评分接口的确定性失败。

跨模型转移：同一家族明显，跨家族几乎抵消

模型 Vanilla + deliverable_landing_gate 谱系 变化 解读
DeepSeek V4 Pro 63.4% 76.9% +13.5pp 被调优模型；这里测试的是中途 harness，不是 final frontier
DeepSeek V4 Flash 64.6% 79.0% +14.4pp 同模型家族几乎完整转移
Nemotron-3 Ultra 550B 63.8% 64.2% +0.4pp 代码修复与 DeepSeek 特定 prompt 的负效应互相抵消

关键限定：跨模型实验运行的是中途谱系 deliverable_landing_gate，不是最终 matter_audit_allwork；只覆盖三个模型，其中两个属于 DeepSeek V4 家族。因此“代码比 prompt 更可迁移”是有根据的方向性判断，还不是广泛模型族上的封闭定论。

作者公开了最值得信任的“坏消息”

附录不只给最终分数，还记录了错误晋升、provider 首轮失败、重试缺失、认证失效和孤儿进程等测量事故。尤其是 stale-weight bug：challenger 的新权重分数与 incumbent 的旧权重分数被错误比较，导致全面更差的 harness 晋升。公开这类失败增强了实验可信度，也提醒我们：harness 优化首先是一项测量工程。

LIMITS, TECHNICAL DEBT, AND PRACTICAL USE

这篇文章最有价值，但也最容易被口号化的地方

证据较强

Vanilla harness 严重低估了模型

固定模型、judge 和测试集后，优化支架让 pooled rate 提升 16.7 点；最大跳升能对应到清晰的文件交付机制。

有条件成立

确定性代码比 prompt 更可靠

本次搜索结果支持这个方向，但 proposer 明显更多探索代码候选，不能据此宣布提示词路线已经穷尽。

尚未证明

训练模型不再重要

搜索在实质性法律推理处进入平台期；跨领域、跨 benchmark、跨广泛模型家族的可迁移性仍待验证。

这是一篇研究文章，不是同行评审论文

材料以 Hugging Face Space 研究文章形式发布，并给出自引 BibTeX、代码仓库和运行产物；PDF 没有 arXiv 编号或正式会议版本。应把它视为透明度较高的实验报告，而不是已经经过独立审稿与复现的定论。

Held-out 是真的，但不是官方隐藏测试集

Harvey 没有公开官方 train/test split。作者在 1,251 个公开任务上按固定 commit 和 seed 自建 24 题 dev 与 100 题 test，并强制纳入若干最难样例。Test 对搜索循环保持隐藏，也做了 leakage audit；但划分、实现和报告都由同一团队控制，外部复现仍很重要。

24 个开发任务决定了搜索能看见哪些失败

Dev set 每个 practice area 仅一题。它便宜到足以迭代，却可能漏掉大量稀有故障。22 次候选评估也会形成多重比较与局部搜索风险；单 frontier 的 copy-and-adapt 容易沿早期成功路径继续爬，而不会主动保留暂时落后、组合后可能更强的机制。

LLM judge 是可用 verifier，不是客观真值

Sonnet 4.6 按 rubric 逐项评分，100 题测试约需 6,300 次 judge call。Criterion 级信号足够稠密，能支撑搜索；同时它也可能受措辞、文件组织和 judge 偏好影响。文章证明了“在这套 verifier 下可以爬升”，不能自动等价为真实律师对所有交付物的质量判断。

通用 harness 对比说明分差很大，但不完全是公平产品赛

Pi、Goose 和 mini-swe-agent 在同模型、同 judge、同任务下运行，这是有价值的控制；但它们没有包含 Meta-Harness 后来发现的 LAB 专用交付机制，也未必为法律文书工作做了同等程度的适配。更稳妥的结论是“通用支架不能被默认视为中性基线”，而非“这些框架本身普遍很差”。

成本没有消失，只是从训练转向搜索与评测

文章报告一次 100 题 test run 约 120–160 美元；24 题 × 3 trials 的 dev evaluation 也在相近范围。模型权重没有训练，但 proposer 会话、长轨迹执行、三次重复和 criterion 级 judge 仍然昂贵。更便宜且校准良好的 verifier，可能比更强 proposer 更能扩展这条路线。

对实际 Agent 工程，最值得带走的是一条排障顺序

  1. 先定义可机器检查的交付契约：文件、路径、命名、格式、必需字段、结束条件。
  2. 再把执行故障与能力故障分开：provider 重试、tool-call repair、幂等恢复、循环检测和日志完整性。
  3. 再做任务一致性检查：输入是否属于当前事项、输出是否覆盖所有交付物、关键数字是否可核对。
  4. 最后才调 prompt、换工具或换模型：只有当前三层都过关后，残余错误才更接近真正的模型能力上限。

一句话判断：标题最合理的读法不是“停止训练模型”，而是“在把失败归因给模型之前，先证明你的 harness 没有浪费它已有的能力”。这是一条实验纪律，也是一条很实用的工程优先级。
