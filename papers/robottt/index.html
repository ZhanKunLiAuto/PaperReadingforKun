LONG-CONTEXT CONTROL · TEST-TIME TRAINING · FAST WEIGHTS

RoboTTT

它没有让机器人在每一步重新翻阅 8K 个历史时刻，而是把经历压进一个会在推理时持续做梯度更新的小型神经网络：历史不再只是 token 缓存，而变成随 rollout 演化的参数。

Yunfan Jiang、Yevgen Chebotar、Ruijie Zheng 等 11 位作者 NVIDIA、Stanford University、The University of Texas at Austin arXiv v1 · 22 页
研究目的

把机器人策略从“只看当前画面或极短历史”推进到 8K 个视觉—动作时刻，同时让单步推理成本不随已走过的上下文继续增长；如果模型能学会把重要经历写入固定大小的状态，它就有机会记住装配进度、遮挡前的信息、刚刚犯过的错误，以及一段人类视频展示的新配置。

核心结论

第一，RoboTTT 真正改变的是“机器人状态长什么样”。普通 Transformer 把历史留在 token / KV 空间，普通 RNN 把历史压成向量；RoboTTT 则让一个两层 MLP 的参数充当递归状态，每一步先用自监督损失更新参数，再用当前 query 读取它。

第二，8K 的价值来自预训练更新动力学，而不只是部署时多走几步。同一 RoboTTT 从 1K 预训练上下文的 43.9% 升到 8K 的 71.5%，相对提高 62.9%；下游 post-training 仍只用 1K，说明长跨度主要在预训练中塑造了“怎样持续写入”的规则。

第三，视频模仿与在线恢复都依赖“上下文和监督目标分工”。人类视频、机器人失败动作可以只更新快权重而不进入模仿损失；真正的机器人动作或人类纠正再作为 target。模型学到的不是盲目模仿失败，而是利用失败判断下一步怎样纠正。

第四，这还不是通用机器人记忆的最终定论。证据来自一个双臂平台、三个桌面装配任务和一个 GR00T 骨干，每个条件只有 10–20 次 rollout；论文也没有给绝对延迟、显存或 GPU-hours 对照。

READING OBJECT

快权重不是“现场微调整个机器人”，而是模型内部的参数化记忆

FAST WEIGHTS（快权重）

英译中：在训练和推理过程中都会快速变化、用来承载当前序列信息的一小组参数。

怎么理解：RoboTTT 每层有一个两层 MLP，参数记作 W。它不是部署后永久改写基础模型，而是在一次 rollout 内从学到的初始值 W₀ 出发，边看边更新，并把 Wₜ 传给下一时刻。

SLOW WEIGHTS（慢权重）

英译中：常规模型参数，包括 VLM、DiT、TTT 投影和门控等。

怎么理解：它们在训练阶段学会“什么值得写、怎样写、怎样查”，但推理时保持冻结。在线更新的是 fast model 的 W，不是拿任务标签或奖励对整个 GR00T 做梯度微调。

TEST-TIME TRAINING（测试时训练）

英译中：测试时也执行一个内部学习步骤。

怎么理解：这里的“训练”是用当前 token 自己构造 key→value 预测任务，计算均方误差并更新快权重；它不需要真值动作。外层动作损失再反过来元学习这套内部更新规则，使“自监督写入”对控制任务有用。

SEQUENCE ACTION FORCING（序列动作强制）

英译中：让一条训练序列中的每个动作块独立抽取 flow-matching 噪声等级。

怎么理解：它不是传统 teacher forcing 的换名。若整条序列共享一个噪声等级，所有动作块会一起变得过易或过难；独立抽样让不同时间点同时覆盖不同去噪难度，论文消融显示去掉它后训练几乎失效。

TBPTT（截断式时间反向传播）

英译中：把长序列切成短段，只在段内传播梯度。

怎么理解：段边界处快权重的数值继续向前，记忆没有重置；梯度图却被 detach，显存由段长而非整条 8K 上下文决定。它固定的是激活显存，不是总训练计算量。

FAILURE CHAIN

长任务的难点不是动作更多，而是当前画面不再足以决定下一步

长上下文策略同时面对容量、利用和成本三道门

容量：一个普通 RNN 向量要把数分钟密集视觉流压成有限维状态，容易丢掉关键阶段；RoboTTT 用非线性 MLP 参数提升状态容量。利用：保留历史不代表会在正确时刻读出，GDN 在 one-shot 视频中能形成递归状态，却仍会拿错组件或装错顺序。成本：全历史 attention 每一步都要保留和检索更多 KV；快权重只携带固定大小 Wₜ。

训练上下文也是一种“更新步数分布”

1K timesteps 约半分钟，甚至短于论文最短的一分钟任务。若只在 1K 上训练，部署时 W 会被更新到训练从未见过的位置，位置编码也会进入未见区间。8K 预训练不是简单增加一个输入窗口，而是让元学习到的 W₀、投影和更新动力学在更长的连续优化轨迹上接受外层任务约束。

证据边界：“非线性梯度更新比线性递归更会压缩”是作者基于 GDN 对照和 TTT-linear 消融提出的解释。它支持 RoboTTT 的具体设计，却还不足以证明测试时梯度下降必然优于所有其他固定状态模型。

MECHANISM

先在内层把当前经历写入 W，再让外层任务教会它怎样写才有用

写入与读取：隐藏状态变成一组可优化参数

公式拆解 · Eq. 1–2
Wt = Wt−1 − η∇WLFW
LFW(Wt−1; Kt, Vt)
= ‖fWt−1(Kt) − Vt‖²
Ot = fWt(Qt)

这两式回答：如何把当前 token 的关联写进快权重，以及如何用当前 query 从更新后的参数记忆中读出上下文。

Wₜ₋₁ → Wₜ
进入当前时刻前后的 fast weights；本文 fast model 是两层 GeLU MLP。
fW / LFW
参数为 W 的 fast model，以及让 f(Kₜ) 逼近 Vₜ 的自监督均方误差。
Kₜ / Vₜ
当前 token 的 key 与 value 投影；内部自监督任务要求 f(Kₜ) 逼近 Vₜ。
η
可学习的内层学习率；附录说明它建立在 0.1 的基础学习率上。
Qₜ
当前查询；更新完成后再交给同一个 fast model 读取。
Oₜ
携带历史信息的输出，随后参与动作生成。
直觉读法：K/V 像一条“写入指令”，一次梯度下降把它刻进 MLP 参数；Q 是“现在要问的问题”。推理时用的是这条自监督均方误差，不需要真值动作，也没有在线更新整个 GR00T。

真正让这条内部更新服务于机器人任务的是外层训练：动作 flow-matching loss 的梯度穿过 Eq. 1，学习 Q/K/V 投影、内层更新动力学和初始状态 W₀。W₀ 因此通过 gradients of gradients 被元学习；每条 rollout 从 W₀ 开始，再形成自己的短期经历。

门控：先把新记忆分支关到接近零

公式拆解 · Eq. 3
O = tanh(α) ⊙ OTTT
+ Oattn

这条式子回答：怎样在插入 16 个 TTT 层时，不让随机初始化的新分支淹没预训练 GR00T 的能力。

OTTT
跨时间快权重分支的输出。
Oattn
原 DiT attention 路径，作为稳定残差主干。
α
逐通道可学习门，初始约为 0.001，tanh 后让 TTT 起始贡献接近零。
先保住“会做当前动作”的旧模型，再逐维学会什么时候依赖长历史。消融中，单独给 GR00T 添加 register tokens 没有收益，也支持结果并非只来自多了 token。

Sequence action forcing：让长序列里的去噪难度彼此独立

公式拆解 · Eq. 5
Atτₜ = τtAt + (1−τt)ε
Lfm = (1/T) Σt=1T Eτₜ, ε [
‖vθ(Φt, Atτₜ, qt; Wt−1)
− (At−ε)‖² ]

这条公式回答：如何让每个时间点的动作块在共享同一条长上下文时，仍独立覆盖从纯噪声到真实动作的不同去噪难度。

Aₜ
从当前时刻起的 H-step 动作块。
vθ
DiT 的 flow / velocity predictor；它接收视觉语言表征 Φₜ、本体状态 qₜ、带噪动作和历史快权重。
τₜ
每个动作块独立采样的 flow timestep；接近 0 时更像噪声，接近 1 时更像真实动作。
ε
高斯噪声；Aₜ−ε 是直线路径上的目标速度。
Wₜ₋₁
进入该时刻前已经吸收历史的快权重，使同一观测可按任务进度生成不同动作。
整条序列共享一个 τ，会让所有动作块同时过易或过难；独立 τₜ 把难度打散。Fig. 12 中去掉这一设计后，Pup Go Car 几乎无法取得有效进展，是论文最强的训练消融之一。

实现代价：上下文状态固定，但模型和训练并不免费

论文在 GR00T N1.7 的 16 个 DiT 层后各加一个 TTT 层。原 DiT 为 538M 参数，加入后报告约 690M；预训练 30K steps、每次使用 16 张 GB200，只更新新序列层；下游 post-training 20K steps、8 张 GPU、1K context，并微调全部参数。部署在 RTX 5090、30 Hz 的 YAM 双臂系统上。这里的 30 Hz 是控制频率，不等同于已经报告了完整模型的毫秒级推理延迟。

TECHNICAL DEBT & BOUNDARIES

RoboTTT 证明了一个值得追的方向，但“恒定、one-shot、在线提升、scaling law”都要带限定词

第一，恒定的是对历史长度的渐近关系，不是已经证明绝对更快

固定大小 Wₜ 让单步状态不随 rollout 变长，这是明确的架构优势；但论文没有给毫秒延迟、吞吐、推理显存、能耗或与 GR00T / GDN 的对照表。RoboTTT 还增加约 152M DiT 参数，并在每一步执行内层梯度计算。30 Hz 只能说明系统部署频率，不能代替完整延迟基准。

第二，context scaling 与额外训练计算没有完全解耦

各上下文长度都预训练 30K steps，但单样本 token 数随 context 增长；4K 及以下全局 batch 为 64，超过 4K 后降为 16。论文承认长 context 增加训练成本，也没有报告 GPU-hours。因此曲线证明“长 context 配方有效”，还不能把全部增益严格归因于 context 长度本身。

第三，Fig. 8 是整体上升趋势，不是无噪声的幂律

原图没有置信区间、随机种子方差或显著性检验；早期点存在小幅非单调，8K 只是最后一个仍在上升的测试点。“no sign of saturation”不能外推成继续增到 16K、32K 一定提升，更不能据此确定 scaling exponent。

第四，79% 完成分掩盖了长任务仍然很难

主评测中 RoboTTT 完整成功为 Pup 9/20、Circuit 13/20、Gear Bot 2/10；最长五分钟任务仍有 80% rollout 未走完全程。论文没有系统归类最终失败，展示的 Fig. 11 是两次失手后恢复成功的案例，不是失败分布。

第五，one-shot 是同任务内的新配置，不是看一段任意视频就会新技能

模型先在 Circuit 训练配置上接受每个配置 5–20 段人类视频与机器人轨迹的配对训练；测试时只给一段未见配置视频，所有配置使用同一句 “assemble circuit”。这很好地验证了视频条件化，却不等于无需这种训练范式的开放词汇模仿。

第六，on-the-fly improvement 是离线蒸馏出的恢复策略

推理时确实不再需要人类，但模型此前见过 100 条带人类纠正的 DAgger 轨迹。它学会把失败映射到纠正，不是依靠在线奖励在任意部署经历中持续变强。GDN 同样从 Distillation 获益 29%，也说明这部分贡献属于更一般的 sequence-policy 训练法。

第七，8K 是预训练上下文；下游 post-training 仍为 1K

这并非缺点，反而说明长预训练更新动力学能迁移；但页面和二手摘要若把它写成“所有训练阶段都在 8K 上端到端训练”，就会误读方法。TBPTT 又在段边界截断梯度，因此跨段记忆数值连续，长期信用分配并不完整。

第八，外部有效性仍集中在一套硬件与一种骨干

所有真实实验都在 YAM 双臂桌面机器人、四路 RGB 和 GR00T N1.7 上完成。参数匹配 GDN 是有价值的受控基线，但“可插拔到广泛 VLA”目前主要是架构兼容性主张，还需要在不同动作头、机器人形态和开放环境中实证。

第九，作者自己留下的三项技术债

论文明确承认：长上下文训练成本高；内层仍使用通用 key→value 自监督目标，尚未设计机器人专用 TTT objective；RoboTTT 无法处理所有部署失败，未来可与强化学习结合直接优化任务成功率。
