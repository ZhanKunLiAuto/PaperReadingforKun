EMBODIED COGNITION · AGENT CAPABILITY · EDGE DEPLOYMENT

ME-VLM

先分开练专家，再统一物理认知与 Agent 能力

理想汽车 Foundation Model 团队技术报告 · v2：2026-09-22 · 30 页4B / 35B-A3B
研究目的

让模型既看懂物理状态，又能安排任务、调用技能，并根据执行结果修正下一步。

核心判断

最值得借鉴的是“先专门训练，再统一能力”的后训练路线。ME-VLM 在 Qwen3.5 底座上分别强化具身认知和 Agent 能力，再蒸馏成单一部署模型。综合评测有竞争力，但现有证据还不足以证明双能力训练产生了协同增益，或已经带来稳定的真实机器人长任务能力。

“统一”落实到决策层

具身认知负责空间关系、动作可行性和状态变化；Agent 能力负责目标分解、工具调用、验证与恢复。部署时一个模型输出决策，底层运动、抓取等由技能接口执行。两位教师只参与训练；标题中的协调不应读成两个专家在推理时互相对话。［§3.1、§4.3］

会规划，仍可能做不成

“把碗放进篮子”在语言上很简单，却需要确认碗的位置、抓取条件和放置结果。作者针对的缺口是：通用 Agent 的工具使用经验不能替代物理状态判断，而具身问答能力也不自动带来多步执行与失败恢复。直接混合两类强化学习目标可能相互干扰，这是分支训练的动机，尚不是本文消融证实的结论。

METHOD

先学物理，再分开强化，最后合流

第一步：两阶段监督微调（SFT）。先把图像与空间关系、可供性、动作前提对齐，再训练“选动作—预期变化—如何验证”的推理。数据还包含仿真中主动注入扰动后得到的成功与失败恢复轨迹，让错误状态也进入学习范围。［§3.2.1、§4.1］

第二步：从不同起点训练两位专家。Agent 专家直接从原始底座出发，具身专家从 SFT 后模型出发。两支都训练可验证的单步能力，以及能实际执行工具或技能的多轮环境闭环；失败反馈被保留。RL 使用组内相对奖励和 GSPO 的序列级更新，不同任务采用相应的正确性、几何或环境状态奖励。［§4.2］

第三步：让教师纠正学生实际会犯的错。多教师 on-policy 蒸馏（MOPD）先让学生自行生成轨迹，再请适用的教师对同一上下文给出分布，按任务加权缩小学生与教师的差异。这样训练覆盖的是学生实际访问的状态，而不只是教师的示范路径。学生从具身专家初始化，以保留物理表征，再吸收 Agent 能力。论文明确沿用已有 MOPD 范式，创新重点应放在整体训练配方与应用整合。［§4.3，式 4］

DEPLOYMENT & BOUNDARIES

端侧可行性明确，协同增益尚待拆解

端侧优化有可量化收益。视觉 token 经贪心 Max–Min 选择，尽量保留互不重复的特征，再配合 W4A8 量化与 M100 软硬件优化。4B 输入 token 从 4,096 减到 3,328，prefill 从 400 ms 降至 188 ms（约 2.13 倍）；这是联合优化结果，不能全归因于 token 裁剪，也不是完整机器人动作的响应时间。［§5，p12–15］

作者另报压缩后的 4B / 35B 分数保留率为 96.7% / 98.2%，但没有展开逐任务明细；特征多样性也不保证保留每个任务关键细节。缺少完整解码、功耗与闭环耗时数据，仍难直接判断实际控制频率。

训练因果证据不足。报告没有原始 Qwen3.5 对照、混合 RL 与分支 RL 对照，也没有蒸馏前后消融；训练样本规模、配比和关键超参数披露有限。因此“能力组合有效”有最终模型结果支持，“MOPD 解决干扰、产生协同增益”仍主要是方法动机。

真实执行证据以案例为主。机器人展示包括依次收纳物体，以及等绿色碗出现后再放勺子；没有重复试验成功率。驾驶主要测场景理解与问答，也不能等同于闭环驾驶可靠性。截至 2026-09-28，官方仓库的推理代码、训练代码、权重与端侧工具包仍列在待办中，独立复现尚受限制。［§6.3、§7.3；官方 README］
