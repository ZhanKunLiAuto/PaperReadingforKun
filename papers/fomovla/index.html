VISUAL FORESIGHT · POINT TRACKING · TRAINING-TIME SUPERVISION

FoMoVLA

一篇把“未来会变成什么样”和“物体怎样连续移动”接到同一个 VLA 表征里的论文；真正的创新点不是多加两项 loss，而是让终态先验去约束运动预测。

Wei Li 等 12 位作者 理想汽车、中国科学院大学、清华大学 arXiv v1 · 12 页
研究目的

把只根据当前图像和语言直接出动作的反应式 VLA，变成能在表征中同时理解“动作片段结束时场景应到哪里”与“任务相关区域沿途怎样移动”的策略；同时让这些训练监督在部署时大部分被移除，以较小的推理成本换取长程控制和分布外鲁棒性的提升。

核心结论

第一，它不是在推理时运行一个完整世界模型。未来帧特征重建、CoTracker 监督、点轨迹解码和 FCCA 都是训练工具；推理时动作头读取保留下来的 16 个 foresight token，但不再显式输出未来特征或轨迹。

第二，论文的有效增量来自“终点—路径”分工。未来特征给出全局目标状态，稀疏二维轨迹给出局部连续运动；FCCA 再把两者变成条件关系，避免只是把两个辅助 loss 相加。

第三，实验支持更好的模拟器内策略学习和零样本扰动鲁棒性，但没有真实机器人证据。LIBERO、LIBERO-Plus 与 RoboCasa GR-1 Tabletop 都是仿真评测；“机器人操控更强”在这里应读成这些基准内的成功率提升。

READING OBJECT

三个对象：终点、路径，以及真正执行的动作

VISUAL FORESIGHT（视觉预见）

英译中：根据当前观察与指令，提前编码动作片段结束时的视觉状态。

怎么理解：FoMoVLA 不直接生成未来 RGB 图像，而是让 16 个 foresight token 经轻量 MAE 解码器重建末帧的 64 个视觉特征。它关心的是“杯子最终应在盘子里”这类场景变化，不承担每一帧的运动细节。

SPARSE POINT TRACKING（稀疏点跟踪）

英译中：跟踪一小组图像位置在未来多帧中的二维位移与可见性。

怎么理解：224×224 图像被压成 8×8 个 VLM 图像 token，每个 token 对应一个 patch 中心点；冻结的 CoTracker-v3 在训练视频里产生 T 帧轨迹标签，模型再从图像 token 隐状态预测这些位移。它描述“沿途怎么动”，但二维轨迹本身并不等于机器人动作。

动作仍由原来的流匹配头生成

基础策略把当前图像 ot 与语言 l 编成上下文 c，再由 DiT 流匹配头从高斯噪声积分得到 T×D 的动作片段。FoMoVLA 没有替换这一动作生成方式，而是在共享 VLM 上添加训练监督，因此可以移植到不同动作头；论文在 StarVLA-π 与 StarVLA-OFT 上都报告了平均成功率增益。

“未来”是当前动作 chunk 的末帧，不是任意长时规划

foresight 监督目标是 ot+T 的视觉特征，点轨迹也覆盖相同的 T 帧动作片段。LIBERO 取 T=8，RoboCasa 取 T=16。它提供的是局部时域内的终态与运动先验；论文并没有证明这些 token 能形成跨多个 chunk 的显式长期计划。

WHY SEPARATE SUPERVISION FALLS SHORT

旧方法缺的不是更多未来像素，而是终点与路径的因果接合

语言必须先于图像 token

若自回归 VLM 仍按“图像在前、文本在后”排列，因果注意力下的图像 token 看不到完整指令，点轨迹头就难以区分“把杯子放进盘子”和“把杯子放进抽屉”需要的不同运动。FoMoVLA 改成 Instruction → Current Image → Foresight → Action，使每个图像位置在预测轨迹前已经具备任务目标信息。

共享同一批 goal token 反而会冲突

论文尝试让未来重建与运动预测直接共享 16 个目标 token，LIBERO-Long 只有 85.8%，明显低于最终设计的 97.6%。作者把它归因于梯度干扰：未来分支偏好外观与全局场景，轨迹分支偏好空间位移。最终设计让图像 token 承担运动 query，再通过 cross-attention 读取 future token，而不是让两个任务争夺同一表示槽。

MECHANISM CHAIN

三路训练信号怎样汇入一套 VLA 表征

未来特征：用 16 个 token 压缩 64 个 patch 的末帧表示

EMA 教师以动量 μ=0.999 更新，用动作 chunk 的最后一帧产生 64 个目标视觉特征；学生端把 16 个 foresight hidden state 与 48 个可学习 mask token 拼接，通过两层 ViT/MAE 解码器重建全部 64 个 patch。余弦损失抑制绝对尺度影响，16→64 的瓶颈迫使 token 优先保存全局场景变化，而不是逐 patch 记忆纹理。

点轨迹：对每个图像 token 施加 T 帧位移监督

冻结的 CoTracker-v3 从训练视频为 8×8 网格产生归一化二维位移 d* 与可见性 v*。两个 MLP 分别预测位移与可见性；位移回归只统计可见点，另加二阶时间差分惩罚，避免轨迹突然折返。这个设计比稠密 16×16 网格更好：后者在 LIBERO-Long 从 97.6% 降到 94.8%，说明监督更密并不自动更有效。

公式拆解 · 终态怎样进入运动预测
H̃vis = Hvis + MHA(LN(Hvis), LN(Hfut), LN(Hfut))

这条公式回答：每个空间图像 token 在预测点轨迹前，怎样读取全局未来状态，同时不破坏预训练 VLM 的原始表征。

Hvis
64 个图像 patch 在 VLM 中的隐藏状态，同时充当 query；每个位置最终要预测一条 T 帧轨迹。
Hfut
16 个 foresight token 的隐藏状态，同时充当 key 与 value，提供动作片段末帧的全局目标先验。
MHA
8 头交叉注意力。输出投影零初始化，使训练开始时附加项为 0，模块先等价于恒等映射，再逐步学习终态条件。
残差 +
保留原 Hvis 的空间内容，只把 future 信息作为增量写入，降低一开始扰乱预训练特征的风险。
直觉读法：一个 patch 想判断自己下一步往哪动，先用自身位置去询问“任务完成时整个场景应该是什么样”。FCCA 只服务于训练期轨迹头；它对动作策略的影响来自联合梯度，而不是推理时显式输出一条点轨迹。

总损失把动作作为主任务，另外两支只做辅助

L = Laction + λ1Lforesight + λ2(Ldisp + Lvis + λsmoothLsmooth)，实现取 λ1=0.1、λ2=0.3、λsmooth=0.1。

轨迹监督的总权重高于未来重建，但二者都不替代动作 loss。训练新增 60.7M 参数（约 +1.3%），包括 30.5M 未来解码器、26.2M FCCA、2.6M 位移头和 1.3M 可见性头；部署参数回到与基线相同的 4599.3M。

证据链最稳的部分

组件消融与设计消融互相咬合。单独 future、单独 tracking、直接相加、FCCA 耦合形成递进；共享 goal token 的失败又反向支持“分工后交互”的设计。相比只报一个主表，这组证据更能说明收益为何出现。

TECHNICAL DEBT & BOUNDARIES

它证明了训练监督有效，还没有证明显式世界模型已经形成

证据较强

终态与轨迹是互补监督

两个分支单独、合并与 FCCA 耦合的消融方向一致；LIBERO 与 RoboCasa 都显示联合训练优于基础骨干。

只能有限外推

“零样本”仍在模拟器族内

LIBERO-Plus 改变相机、机器人状态、语言、光照、背景、噪声和布局，但不是跨真实硬件、跨控制频率或跨实验室迁移。

仍待验证

token 是否真的预测可执行未来

定性 PCA 图和教师轨迹误差显示内部一致性，但没有反事实规划、失败恢复或多步未来校准实验来证明它形成了可查询的世界模型。

第一，二维点轨迹不包含深度与三维动力学

作者在结论中明确把这一点列为限制：当前监督只描述依赖视角的图像平面运动，无法显式表示动态场景的三维几何。相机移动会把全局 ego-motion 与局部操作运动叠在一起；RoboCasa 定性结果虽显示模型能一定程度拆分二者，但 LIBERO-Plus 的相机维度仍不是最强。

第二，所有策略成功率来自仿真

LIBERO 有 4 套件 × 10 任务，每任务 20 次 rollout；RoboCasa 有 24 个任务，每任务 50 次；LIBERO-Plus 有 10,030 个扰动实例。覆盖面不小，但都没有执行噪声、传感器延迟、真实遮挡、机械磨损和安全约束等现实变量，不能据此声称真实机器人成功率已经提升。

第三，结果缺少方差、置信区间和多随机种子

主表以单个成功率呈现，没有报告不同训练种子或 bootstrap 区间。对于 FCCA 相对直接相加仅 +0.5 pp（LIBERO）和 +0.3 pp（RoboCasa）的增量，统计不确定性尤其重要；现有结果支持机制方向，但不足以精确判断协同增益的稳定规模。

第四，“无额外推理开销”需要拆成两句话

附录显示部署参数确实与基线同为 4599.3M，因为 60.7M 辅助参数全部删除；但 16 个 foresight token 仍要穿过 VLM，单张 H20、batch 1 下中位延迟从 94.3 ms 增至 103.7 ms，约 +10.0%，显存从 9.3 GB 增至 9.4 GB。更准确的说法是“无额外部署参数，推理成本小幅增加”，而非字面上的零开销。

第五，未来监督依赖训练视频和外部教师质量

训练时必须取得动作 chunk 的未来帧，EMA 教师决定什么视觉特征算“正确未来”，CoTracker 决定什么二维轨迹算“正确运动”。遮挡、反光、快速相机运动或教师漂移会把误差作为监督写入 VLM；论文没有给出教师置信度过滤、错误轨迹鲁棒性或无未来视频数据时的训练方案。

第六，计算账只覆盖推理，没有完整训练成本对照

作者报告训练参数增加 1.3%，并给出 8×H20、LIBERO 30K step、RoboCasa 100K step 的设置，但没有量化 CoTracker 预处理、EMA 教师前向、MAE 与 FCCA 带来的训练吞吐和总 GPU 小时变化。训练期“轻量”仍缺少完整成本曲线。
