FastHarness

把贵的监督留给陌生状态和失败恢复

Tao Lin 等 · 13 页2026-10-22 · 用户提供的 PDF 版本

总体判断：FastHarness 最值得借鉴的是把外部大模型监督视为需要调度的资源：熟悉且多次审查成功的阶段减少复核，遇到陌生情境、过去错误或恢复过程重新密集审查。策略权重不变、每个动作块仍从新观测生成，节省的是复核，不是反馈控制。四项 RoboDojo 仿真任务中，首个评测 episode 到最后五次均值的单任务 token 降幅平均为 57.2%，平均总用时从 85.5 降至 52.0 分钟。成功率 97.19% 相对外部报告 80% 是有希望的结果，但不同样本构成与共享记忆使它不能被当成严格独立、配对的因果增益。〔§5，附录B、D〕

这个系统的“学习”发生在阶段样本、审查计数和错误记录中，并未更新 π0.5。它不回放旧动作、不复位仿真状态；旧经验只影响何时检查、该向哪个已经验证过的子目标纠正。

三种模型与三种成功需要分开

π0.5 是连续动作策略：读取三路 RGB、关节和末端状态，为双臂提出动作块。GPT-6 Astra 是论文使用的 reviewer，审查最近执行和新提案，批准或提出纠正。Harness 是外围运行逻辑，负责记忆检索、决定审查、管理恢复状态。模型名称和能力描述均按所供报告，不代表本页独立验证产品能力。〔§3–4，附录B〕

审查的 ok 只说明上一段普通策略转移被 reviewer 判为成功；“恢复完成”只说明故障被 reviewer 判定解决；整个任务成功由环境 native_success 决定。原文有审查一直进行却未察觉任务失败的案例，说明这三层结果不能互换。

同一任务多次执行连接成 memory chain，场景布局变化而任务记忆保留。跨链通过任务、策略配置、特征表示、reviewer 配置/协议等哈希分区。它研究重复任务中的经验累积，不是任务完全未知时的通用在线自进化。

每个动作块都找大模型检查，为什么会慢？

逐块审查的主要费用来自服务等待和长上下文，熟悉任务的重复片段也会付同样代价。Fold clothes 和 Bottle disposal 两条完整 20 次记忆链中，reviewer 交互分别占总墙钟时间 82.0% 与 89.7%，记忆操作少于 0.1%。因此减少不必要调用有明确的系统瓶颈依据。〔图6，§5.4〕

但审查稀疏之后不能把未审查片段自动算成成功。作者仅将明确判定的、紧邻此次审查之前的普通策略转移计入成功/失败统计；恢复动作和更早的未审查块不获得臆造标签。这避免把缺少错误报告错当成大量成功证据，也意味着统计只代表被选择审查的状态。〔附录A.1〕

快路径和恢复路径怎样协调

阶段记忆是一种非常具体的近邻表

每个观测压缩成 590 维：三幅 8×8 RGB 缩略图共 576 维，加 12 个归一化关节角和 2 个夹爪量。每阶段保留最近 128 个不同样本，用归一化均方根距离匹配。最近距离超过 0.06 为陌生，两最近阶段距离差小于 0.01 为含糊；这两类都触发审查。缩略图只给 harness 检索，策略和 reviewer 保留各自的正常观测输入。〔附录A.1〕

审查间隔由保守得分和样本量共同决定

对阶段 s，S/F 是已审查普通策略转移的成功/失败次数，r 是以 z=1.96 算出的 Wilson 下界。少于 m=2 个样本，或发生过错误后连续成功不足 3 次，间隔固定为 1。否则 I=1+⌊(L−1)r²·min(C,T/m)⌋，L=20、C=6、T=S+F。L 是尺度而非硬上限。r 可作为保守启发式，但选择性审查与链内相关性不满足直接把它解释为严格独立 Bernoulli 安全保证的条件。〔附录A.2〕

计划间隔还会被更高优先级条件打断：新 episode、恢复中、陌生/含糊、上次不确定、提案警告、靠近历史错误、控制步上限等。随机审计概率为 0.03；相同阶段错误距离≤0.04 时，即使错误已恢复、阶段整体成绩很好，也仍要求检查。基础上限为从最近审查观测起 120 个控制步。计划的块间隔和实际连续自动执行长度是两种量。

恢复不是把状态倒回去

发生执行错误或意图不匹配后，每个块都审查。先本地修复；两次尝试未成功时，如果本 episode 有更早、合格且没试过的 waypoint，策略在当前环境生成新动作朝它纠正。一次尝试至多执行 8 个块而无成功判定。达到旧子目标后仍须单独验证原故障，至少再执行一个块，才可以恢复普通调度。错误记录长期保留。〔附录A.3〕

切换调度状态，看审查旁路何时开启、恢复时为何重新接入逐块监督。依据图2与附录A；结构示意。

熟悉且稳定

新观测 → π0.5 新动作块
→
阶段匹配 + 经验间隔 + 强制触发检查
→
符合条件 → 跳过本次大模型复核
→
执行允许的前缀 → 获取新观测

跳过 reviewer 不等于开环执行旧轨迹；每块都重新观测和求策略。

陌生或历史错误附近

新观测 + 新提案
→
陌生 / 含糊 / 错误邻域触发
→
GPT 审查 → 记录上一普通转移结果
→
批准或纠正 → 执行

记忆更丰富也不会取消错误邻域的强制检查。

恢复进行中

已识别故障
→
每块 GPT 复核 → 本地修复
→
必要时朝已验证 waypoint 生成新动作
→
验证子目标 + 单独确认原故障 → 结束恢复

waypoint 是当前世界里的纠正目标，不是环境 reset。

97.19% 是四任务等权平均，不是把全部试验池化后的成功率。57.2% 是四个任务百分比降幅的平均；1.83→0.93 百万是每任务 token 数的均值，二者分母不同，不能要求其比值恰等于 57.2%。缓存输入计一次，这些是记录的 token 用量而非美元成本。〔图4–5，表5–7〕

用时包含策略、机器人执行、reviewer 请求处理/等待/重试及其他开销。四任务首个评测 episode 到末五次平均分别为 54.1→25.2、40.4→12.2、70.5→36.4、177.2→134.2 分钟。它支持降低服务主导的墙钟成本，但仍然不是可直接用于实时部署的低延迟系统。

外部 GPT-as-Policy 混合基线每任务仅 5 个 case；Fold clothes 含 2 个标准和 3 个随机 case，其他任务为标准 case。FastHarness 使用各任务 standard 配置、多次布局及共享记忆；Build tower 的首个评测 episode 还已经有先前任务经验。作者明确说明基线来源，故应该认可描述性提升，同时避免把 17.19 个百分点全部归因于调度算法。〔附录B.2、D〕

恢复与失败案例比单个平均数更有信息

Bottle disposal 第19次执行中，瓶子掉落后重新靠近、抓起并恢复运输；局部恢复窗口花费 161,222 token、480.15 秒，且不含触发审查与退出后的重新规划。Classify objects 前8次的16个恢复事件都回到普通调度，但一次事件可含多次尝试，不能当作16个独立成功试验。〔附录C〕

相反，Fold clothes 第17次共20次审查而没有启动恢复，最终 native score=0.2 且任务失败。它清楚表明：监督省下多少是一条证据链，监督是否识别了真实错误是另一条；复核频繁也不自动保证任务级正确。

可采用的是调度接口，尚缺严格的贡献分离

目前最强结论是四个已研究任务的共享记忆链中，监督负担随经验下降，并维持较高任务成功。尚缺同场景、同 reviewer、相同随机种子下的 always-review、无记忆、无恢复、固定间隔等受控消融，因此快路径、恢复机制、任务暴露次数各自贡献多少仍未隔离。

590 维缩略图距离容易受相机、光照或细小物体变化影响。原文给出了明确阈值和未知状态回退，有利于复现，但没有证明这些数值可跨硬件、跨场景直接使用。更适合的验证是固定评测场景和计算预算，分别干预视觉变化与物理危险，观察陌生触发是否既灵敏又不过度调用。

记忆链内 episode 相关，作者也明确不把恢复事件视为独立试验。效率初末比较可能同时受场景难度、服务排队与任务熟悉度影响；随机顺序重复链和统一服务计时能更好区分它们。无论这些不确定性如何，论文已经具体展示了“持续新观测控制 + 可审计的选择性监督”这一值得复用的系统设计。
