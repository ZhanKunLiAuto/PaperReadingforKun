AR-TO-DIFFUSION · BLOCK-CAUSAL ATTENTION · HIERARCHICAL DISTILLATION

WAM-Diff2

它不重新训练一个只会规划的扩散策略，而是尝试保住成熟自回归 VLA 的理解、感知和规划能力，再把逐 token 解码改造成块内并行、迭代去噪的离散扩散。

Zhihao Zhu、Hanlin Shang、Mingwang Xu 等 9 位作者 复旦大学、颖望智能技术有限公司 arXiv v1 · 16 页
研究目的

把预训练自回归驾驶通才转换成可并行解码的多任务离散扩散 VLA，同时尽量保住场景问答、目标定位和轨迹规划能力；核心要解决的不是一个普通模型压缩问题，而是因果注意力与双向注意力、next-token 训练与迭代去噪之间的架构范式断层。

核心结论

第一，论文真正解决的是“架构翻译”，不是提出一个全新的驾驶 backbone。视觉编码器、统一 tokenizer 和 decoder-only Transformer 继承 Qwen3-VL；创新集中在 block-causal mask、masked discrete diffusion 以及三级蒸馏课程。

第二，同范式教师比更强但异范式教师重要。2B 扩散学生从 8B 扩散教师蒸馏得到 88.3 PDMS；换成 8B 自回归教师只有 79.9。Top-K token 分布重合也更高，支持“先完成 AR→Diffusion，再做跨尺度压缩”的顺序。

第三，“性能等价”和“15.1×”都要加限定词。任务专用规划中 B=32 与 AR 基线相当或略高；统一多任务 checkpoint 在 DriveBench、LingoQA、COCO 和 NAVSIM 上仍有 0.7–2.9 分损失。15.1×是 token decoding latency 在叠加 CUDA 系统优化后的结果，不是整条传感器到控制链的端到端加速。

READING OBJECT

三个概念：暴露偏差、吸收态离散扩散与块因果注意力

EXPOSURE BIAS（暴露偏差）

英译中：训练时模型总看到正确历史 token，推理时却必须继续消费自己可能出错的输出，由此产生训练—推理分布错位。

怎么理解：轨迹坐标被序列化成 token 后，前面一个数值 token 的误差会成为后面所有 token 的条件。自回归模型不能回头改早期承诺；块扩散则在同一 block 内反复查看并修改整组 token。

ABSORBING DISCRETE DIFFUSION（吸收态离散扩散）

英译中：正向过程逐步把真实 token 替换成不会再恢复的特殊 [MASK] 状态，反向模型学习从被遮序列重建干净 token。

怎么理解：推理从全 [MASK] 开始，每一步并行预测所有位置，固定高置信 token，再把低置信位置继续遮住重猜。计算步数由 denoising step T 决定，而不是输出长度 L；论文观察到大多数任务在 8–16 步附近饱和。

BLOCK-CAUSAL ATTENTION（块因果注意力）

英译中：同一生成块内 token 可以双向看见彼此，不同块之间仍保持从前到后的因果依赖。

怎么理解：B=1 时每个块只有一个 token，退化为标准 AR；B 越大，同步精炼的 token 越多、硬件并行度越高，但从原始 causal 模型迁移的难度也越大。B=32 是论文最终高吞吐配置。

多任务统一来自输出接口，而不是三个独立 head

图像、指令与 noisy response token 进入同一 token 空间；驾驶问答输出自然语言，COCO grounding 输出 JSON 坐标，NAVSIM 输出 8 个未来 waypoint 的扁平坐标序列。任务身份由指令和输出格式隐式指定，没有任务专用 projection head。这也解释了为何坐标量化和严格格式会成为扩散解码的敏感点。

WHY DIRECT CONVERSION FAILS

把 causal mask 一次换成双向 mask，会同时打破注意力习惯与训练分布

为什么普通 off-policy 蒸馏不够

如果扩散学生只在干净目标或 AR 教师产生的序列上学习，它仍未见过自己推理时造成的中间错误。Stage II 把 teacher 与 student 放在相同的 corrupted state ỹt 上比较，使训练输入更接近学生真实去噪路径。论文借鉴 on-policy 思路，但公式描述的是对同一噪声状态的分布蒸馏，并非完整在线 rollout 强化学习。

为什么跨尺度蒸馏要等到两边都变成扩散

8B AR 与 2B diffusion 即使面对同一上下文，也会因为可见性和迭代状态不同而形成不同 token 分布；8B diffusion 与 2B diffusion 的“思考模式”更一致。Top-5 预测集合重合率从 AR 教师的 51.2% 提高到 diffusion 教师的 58.2%，对应 PDMS 从 79.9 恢复到 88.3。

MECHANISM CHAIN

三级蒸馏怎样把一座断桥拆成可以走的小台阶

公式拆解 · 正向遮挡与反向并行精炼
Qt = (1−βt)I + βt1emask⊤,   pθ(o0|ot,c)

这组公式回答：训练时怎样便宜地采样任意噪声状态，以及推理时模型究竟在预测什么。

βt
第 t 步的遮挡概率；越大，更多 token 被送入吸收态 [MASK]。
I
保持 token 原样的身份转移；1emask⊤ 把 token 送到统一 [MASK] 状态。
ot
任意噪声时刻的 token 序列，可由闭式边缘分布直接采样，不必逐步执行完整正向链。
pθ
给定多模态条件 c 与 noisy tokens，直接预测干净序列；推理中高置信位置固定，低置信位置继续重猜。
直觉读法：训练时随机把答案的一部分涂黑，模型学习一次看整块并补全；推理时先全涂黑，再用少量轮次逐渐把最有把握的答案“显影”。
公式拆解 · 为什么用对称 JSD
JSD(p∥q) = ½KL(p∥(p+q)/2) + ½KL(q∥(p+q)/2)

这条公式回答：怎样在同一 noisy state 上对齐教师与学生 token 分布，同时避免只让一方覆盖另一方的单向偏置。

p
稳定小块或 8B 扩散教师在某个 token 位置的完整词表分布。
q
大块或 2B 扩散学生在相同条件与 noisy state 下的分布。
(p+q)/2
两者混合分布；让 teacher→student 与 student→teacher 两个方向都参与约束。
直觉读法：既不只追教师最高峰，也不只要求覆盖教师所有尾部。论文中 JSD 为 88.3 PDMS，forward KL 为 88.2、reverse KL 为 88.0；方向符合作者解释，但 0.1–0.3 的差距很小，不能单凭这张表断言 JSD 普遍最优。

训练账：语义地基、注意力迁移与蒸馏都不是免费

统一多任务语料含 981,361 个样本：NAVSIM 103,288、DriveLM 346,978、LingoQA 413,829、COCO detection 117,266；另有 SimLingo 2,024,407 个闭环规划样本。全局 batch 128、32 张 Ascend 910C；附录表列出三个阶段 1,376、240、264 NPU 小时。若已有成熟 AR VLA，可跳过可选的多任务 AR 预训练，但渐进适配和蒸馏成本仍在。

直接转换的损失主要落在 DAC 与 EP；块级蒸馏找回绝大部分性能，模型级蒸馏再补 0.6。最终比 AR 高 0.2，数值上是追平而非大幅超越。实验没有报告多随机种子，因此 0.2 的优势不宜被解释为稳定的算法超越。

第三本账：长时误差更小，但证据来自成对 open-loop waypoint

Bench2Drive：总体闭环指标略降，部分安全子项改善

AR baseline 的 Success Rate / Driving Score 为 51.96% / 80.51，B=32 为 49.55% / 78.93，整体略低；Emergency Braking 从 60.34% 升至 61.67%，但 Traffic Sign 从 89.25% 降至 85.26%。因此闭环表支持“高并行配置仍有竞争力”，不支持“所有闭环鲁棒性都优于 AR”。

证据链最稳的部分

逐级消融 + 教师范式对照 + token 重合率共同支持层级转换策略。直接转换会崩，扩散小块教师能恢复，扩散大模型比 AR 大模型更适合教扩散学生；速度收益也随 B 增大而连续上升。证据最弱的是把很小的最终分数差和 open-loop 误差外推成普遍闭环优势。

TECHNICAL DEBT & BOUNDARIES

它给出一条可扩展转换路线，但离“无损、通用、端到端高效”还有距离

证据较强

渐进、同范式蒸馏优于直接转换

84.1→87.7→88.3 的累计消融，以及 diffusion teacher 88.3 对 AR teacher 79.9，形成一致证据链。

只能有限外推

15.1×是解码栈加速

它来自 diffusion、FlashInfer 和 CUDA Graph 的叠加，不等于视觉输入到车辆控制的端到端时延缩短 15.1×。

仍待验证

真实道路闭环与跨 backbone 迁移

方法只在 Qwen3-VL 家族与仿真/离线驾驶基准中验证，尚未展示真实车、异构 VLA 或安全关键长时闭环。

第一，离散坐标 token 会引入量化与格式脆弱性

轨迹点与 bbox 都由统一文本 tokenizer 输出。论文自己指出空间量化可能破坏高精度轨迹平滑度；COCO mAP 也随 B 增大从 39.2 降到 36.3，比规划更早出现退化。连续动作解码、残差细化或混合离散—连续 head 是自然补丁。

第二，学生上限受初始 AR 教师语义能力限制

三级蒸馏能保住或搬运已有知识，不能创造教师从未学会的场景理解。论文把 Stage III 描述为继承 8B 高层能力，但统一多任务 B=32 仍低于 2B AR 基线多项指标，也没有展示超越 8B 教师的知识发现。

第三，训练与部署硬件账分开，跨平台结论要谨慎

模型质量与大规模训练在 Ascend 910C 上，FlashInfer 与 CUDA Graph 的最终优化在 CUDA 平台上单独测量。这样可以证明实现路线可行，却不能直接给出一套单一硬件上的完整“质量—延迟—功耗”Pareto；车端部署还关心内存、功耗、编译稳定性和 batch=1 抖动。

第四，解码 TPS 不是控制频率

不同任务输出长度不同，diffusion 还要运行 8–16 个去噪 step。每 token 延迟与 TPS 适合比较生成内核，但自动驾驶真正关心的是一轮多相机编码、文本/状态融合、整段轨迹生成和控制下发的 p50/p99 时延。论文没有给出这条端到端链的统一数字。

第五，高分系统结果混入外部候选选择

NAVSIM 的 91.1/90.7 带星号，使用 score-based candidate selection；原生模型是 88.3/88.6。候选选择可以显著提高规划质量，但也引入额外计算与模型组件。评价“扩散解码器本身”时必须使用无星号结果。

第六，稳健性主张仍缺强闭环统计

12,146 个 NAVSIM 样本显示远期 waypoint 误差改善，是漂亮的成对证据；Bench2Drive 的 B=32 总体 Success Rate 与 Driving Score 却略低于 AR。论文没有报告多训练种子、置信区间、真实车辆干预次数或长时故障恢复，因而“缓解暴露偏差”比“提升闭环安全”更有证据。

第七，训练流水线仍然昂贵

论文把它定位成 low-cost 转换管线，但附录列出的三阶段合计 1,880 NPU 小时，另需构造 8B B=32 diffusion teacher。已有 AR VLA 时可跳过第一轮多任务预训练，却仍需要多 block size 适配、递归蒸馏和跨尺度蒸馏；“低成本”应相对于从头训练通用扩散 VLA，而不是绝对成本。
